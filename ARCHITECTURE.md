## 2. Backend Architecture (`backend/src/main/scala/durak/`)

### 2.1 Pure Game Engine (`durak.engine`)
All core rules reside in side-effect-free Scala 3 case classes and enums:
- **`Card`, `Suit`, `Rank`:** Models suits (`Clubs`, `Diamonds`, `Hearts`, `Spades`) and ranks (`Two` through `Ace`, supporting 36-card decks for 2–3 players and 52-card decks for 4 players).
- **`GameConfig`:** Stores `playerCount`, `allowRedirect`, `seed`, and `playerTypes` (per-seat `"human"` / `"randomBot"` / `"basicBot"`; any seat the vector does not name is human). `config.seatType(idx)` returns the canonical seat type (`GameConfig.HumanSeat`, `RandomBotSeat`, `BasicBotSeat`), `config.isBotSeat(idx)` is true for both bot kinds, `GameConfig.canonicalSeatType` maps accepted spellings (case/padding-insensitive, with `"bot"` as the random shorthand) and falls back to a human seat for unknown values, and `GameConfig.normalizePlayerTypes(playerCount, types)` pads/truncates and canonicalizes a request's seat list.
- **`GameState` & `BoutPhase`:**
  - Tracks `players: Vector[PlayerState]`, `talon: Vector[Card]`, `bottomTrumpCard: Option[Card]`, `trumpSuit: Suit`, `discardPile: Vector[Card]`, `tablePairs: Vector[TablePair]`, `attackerIdx: Int`, `defenderIdx: Int`, `boutPhase: BoutPhase`, `winners: Vector[String]`, `durak: Option[String]`, and `presentPlayers: Set[String]` (human seats that reported an open connection). Presence is derived through `isPresentSeat(idx)` / `isPlayerPresent(id)` / `presentPlayerIds`, and bot seats are always present.
  - **Card Conservation Invariant:** Across all transitions (`InitialAttack`, `CoverCard`, `RedirectAttack`, `ThrowInCards`, `DeclareSurrender`, `PassTurn`, and bout resolution draws), total cards across `talon + discardPile + hands + tablePairs` remains strictly constant (`36` or `52`).
  - **Last-Player-Standing Victory:** Players who empty their hands once `talon.isEmpty` are appended to `winners` in order of finish and skipped by clockwise turn helpers (`nextActivePlayer`). Play continues until `activePlayersWithCards.size <= 1`, designating the final remaining player holding cards as `durak`.
  - **Chaos Mode Variant (not implemented in the engine yet):** `GameAction.InitialAttack` carries no target seat, so an opening attack always aims at the clockwise defender. Selecting an arbitrary target still requires a target-aware variant in `GameAction` / `GameEngine`.

### 2.2 Anti-Cheat State Projection (`PlayerGameView`)
- `PlayerGameView.forViewer(state, viewerId)` strips all hidden information before serialization.
- A connected client receives only their own `myId` and `myName` (their display name, `""` when an older payload omits it; encoded as `"myName"` and decoded with an `Option[String].map(_.getOrElse(""))` fallback) plus `myHand: Vector[Card]`, public summaries for opponents (`id`, `name`, `cardCount`, `hasPassed`, `finishRank`, `isPresent`), `talonCount`, `bottomTrumpCard`, `trumpSuit`, `tablePairs`, `legalActions`, `turnDeadlineMs`, and `presentPlayers` (ids of every present seat, in seat order) so the UI can draw green/grey presence dots. It also carries `promptedPlayerIds`, the discard summary (`discardCount` plus `lastDiscardCards`, the revealed top of the pile) and the overall clock (`gameStartedAtMs`, `gameEndedAtMs`, which freezes once the game ends).
- **Finished-game projection (`boutPhase == GameOver`):** `forViewer` is total for every valid seat (`p0..pN`) and for a draw in which all hands are empty: the clock is idle (`turnPlayerId = None`, `turnDeadlineMs = 0`, `turnSecondsRemaining = 0`, even if the caller's state still carries a deadline), `legalActions` and `promptedPlayerIds` are empty, `gameEndedAtMs` is populated, and `winners` / `durak` come from `finishOrder`.
- **Throw-in projection:** during `BoutPhase.Defense` a non-defender holding a card that matches a rank on the table already receives `"throwIn"` in `legalActions` while the attack is still uncovered — the defender keeps the turn clock until every attack is covered. Once the table is covered or the defender has surrendered, every eligible thrower is additionally listed in `promptedPlayerIds`, so only they (and never the surrendered defender) hold the clock.

### 2.3 Concurrent Server Actors & Turn Clock (`durak.server`)
- **`GameActor`:** Wraps each match's `GameState` in a `Cats Effect` `Ref[IO, ...]` and broadcasts personalized `PlayerGameView` snapshots over a `Topic[IO, ...]` to connected WebSocket clients. `setPresence(room, playerId, isPresent)` stores presence in the state and re-publishes it whenever the value changes, so presence dots update without anyone having to play a move.
- **Bot seats (`engine/RandomBot`, `engine/BasicBot` + `GameActor.startBots`):**
  - `RandomBot.legalActionsFor(state, playerId)` enumerates opening attacks (every hand card), covers, redirects, surrenders, throw-ins and passes for the seat's role and phase, then keeps only the actions `GameEngine.applyAction(state, playerId, action)` accepts; a finished seat and a surrendering defender get nothing. `RandomBot.chooseAction(state, playerId, rng)` picks one uniformly.
  - `BasicBot.legalActionsFor` delegates to `RandomBot`, so both bots share one engine-filtered move set. `BasicBot.chooseAction` applies a fixed policy: the lowest-ranked non-trump opening attack (a uniformly random trump when the hand holds only trumps), the cheapest non-trump cover/redirect whenever one is legal (surrendering only when none exists), and the lowest non-trump throw-ins — never a trump throw-in, passing once only trumps remain.
  - `GameActor.chooseBotAction(state, botId, rng)` dispatches on `config.seatType`: `BasicBot` for a `"basicBot"` seat, `RandomBot` otherwise.
  - **Strict legal-move invariants (`GameEngine`):** `applyAction(state, playerId, action)` rejects a move issued by another seat (`GameEngine.actorId` names that seat), and `legalActions` filters every candidate through the same guard. `RedirectAttack` requires `allowRedirect`, an uncovered table under the 6-card cap, a matching-rank card in the defender's hand, `nextActivePlayerIdx(defenderIdx) != defenderIdx`, and a next defender holding at least `tablePairs.size + 1` cards — so a cardless opponent (for example one that attacked with its last card) can never become the defender. `CoverCard` and `DeclareSurrender` are defender-only and rejected during `InitialAttack`, `SurrenderThrowIn` and `GameOver`; a seat that is both attacker and defender can never cover its own attack, and during `SurrenderThrowIn` the surrendered defender has no legal action at all.
  - One driver fiber per room (started only when a seat is a bot) submits the chosen move through the same `applyAction` pipeline as a client, so clock restarts, validation, replay recording and broadcasts are shared. `GameActor.botDelayFor(room, state, botId)` decides the pace from `config.seatType(seat)`: a `GameConfig.RandomBotSeat` plays with **`0.millis`** delay (`None`; the loop `IO.cede`s first so fiber scheduling stays fair and HTTP/WebSocket handlers are never starved during an all-`RandomBot` game), while a `GameConfig.BasicBotSeat` keeps the random **`500.millis`–`2000.millis`** window — constructor-overridable for fast tests, but the default stays in that range. The pause races a state-change watch, so a move for a superseded position is dropped instead of played.
  - **`BoutPhase.GameOver` broadcast & replay guarantees:** whichever move reaches `BoutPhase.GameOver` (human, instant `RandomBot`, `BasicBot` or turn-clock auto-action) goes through the same pipeline, which stamps `gameEndedAtMs`, clears the turn deadline, appends the final frame with one frozen `PlayerGameView` per seat to the room's `GameReplay` and publishes the state to the `Topic` — so every connected socket receives the `GameOver` projection immediately. `GameManager` never evicts a room, so `GET /api/games/:gameId/view`, `GET /api/games/:gameId/replay` and `/ws/game/:gameId/:playerId` keep serving a finished match instead of 404-ing or hanging.
  - The prompted seat is the attacker during `InitialAttack`, the defender while an attack is uncovered, and otherwise any un-passed thrower — the same ordering the turn clock uses. Human seats are only ever animated by the turn clock.
- **15-Second Turn Clock & 3-Second Auto-Action Delay:**
  - Every valid state transition resets `turnDeadlineMs = now + 15000`.
  - Background fibers monitor the turn deadline and execute the default timeout move (`InitialAttack` with a random card, `DeclareSurrender` for a defender, or `PassTurn` for a thrower) if 15 seconds elapse without input.
  - Forced automatic actions wait 3 seconds before firing so players can visually read the table state.
- **`GameRoutes`:**
  - `GET /api/health`: Readiness probe returning `200 {"status":"ok"}`; the frontend polls it before offering game creation.
  - `POST /api/games` (alias `POST /api/game/create`): Creates a match with `playerCount`, `playerNames`, `allowRedirect`, and `playerTypes` (`"human"` / `"randomBot"` / `"basicBot"` per seat, canonicalized to exactly `playerCount` entries). The response is `{ gameId, players, playerTypes }`.
  - `GET /api/games/:gameId/view?player=:playerId` (alias `GET /api/game/:gameId/view/:playerId`): Returns that seat's `PlayerGameView` JSON. An omitted or blank `player` falls back to `p0` (`GameRoutes.DefaultViewerId`), so a bare game URL always renders a finished table; only a non-blank id that names no seat is a `404`.
  - `POST /api/games/:gameId/action` (alias `POST /api/game/:gameId/action`): Submits a `GameAction` for a player.
  - `POST /api/games/:gameId/presence`: Body `{ "playerId": "p0", "isPresent": true }` (an `"active"` flag is also accepted) records human presence and returns that seat's view.
  - `GET /api/games/:gameId/replay` (alias `GET /api/game/:gameId/replay`): the recorded match — `gameId`, `moves` with their `elapsedMs`, and `frames` whose `views` hold one frozen `PlayerGameView` per seat, so a review viewer never needs the live room.
  - `GET /ws/game/:gameId/:playerId`: Bi-directional WebSocket streaming `PlayerGameView` updates. Text frames are `{"type":"ping"}`, `{"type":"presence","isPresent":…}` or a `GameAction`; incoming `Ping` / `Pong` frames are ignored silently. Opening the socket marks the seat present and closing it marks it absent.
  - **Keepalive & idle timeout:** the outbound stream merges a `WebSocketFrame.Ping()` every `20 s`, and `Main` raises Ember's idle timeout to `10 minutes` (from the 60-second default), which is what stopped idle tables from dying with `java.util.concurrent.TimeoutException`.

## 3. Frontend Architecture (`frontend/src/`)

### 3.1 Lichess 3-Column Shell & Deterministic 3x3 Table Grid
- **`GamePage.tsx`** renders three non-overlapping top-level CSS Grid columns:
  1. `[data-zone="sidebar-left"]`: `POV` player-switcher tabs (real player names), the `⚡ QA Scenarios` preset buttons (`[data-testid="qa-scenarios"]`, `QA_SCENARIOS` → `createPresetGame`), the How-to-Play reference card, and the replay move-navigation panel once a match is over.
  2. `.table-column`: a flex column holding `[data-zone="table-arena"]` (the central felt table, `GameTable.tsx`) on top and the `HAND SORTING` box (`[data-zone="hand-sort-box"]`, `data-testid="hand-sort-box"`, class `sidebar-box sidebar-sort-box hand-sort-box`) directly below it with a fixed `gap`, so the two can never overlap. `GamePage` owns the `sortMode` state (`'suit'` default) and passes it to both the `SortBar` in that box and `GameTable`.
  3. `[data-zone="sidebar-right"]`: the overall game clock (`mm:ss`, `[data-testid="game-clock"]`), the monospace digital turn clock (`00:XX`), the `PLAYERS` list with presence dots and attacker/defender outlines, the `TableDeck` (`DECK` title + centred talon/horizontal trump/`TRUMP` assembly with a top-left counter oval, plus the discard pile), and the match winner/Durak badges. The right column no longer holds the sort control (ITEM-ADD-7).
- **`PLAYERS` list structure (ITEM-ADD-2 / ITEM-ADD-8a / ITEM-ADD-8b):** every `.status-badge` row is a three-track CSS Grid (`grid-template-columns: minmax(0, 1fr) auto minmax(0, 1fr)`): left `.status-player` (presence dot + `.status-name`, `justify-self: start`), centre `.status-cards` (`${cardCount} cards`, `justify-self: center; text-align: center`) and right `.status-state-slot` (`justify-self: end`). The equal `1fr` side tracks pin the card count to the row's midpoint, so it never moves when a tag appears. While `displayedView.boutPhase` is not `GameOver`, the seat at `attackerIdx` gets `data-role="attacker"` and the seat at `defenderIdx` gets `data-role="defender"` on both the `<li>` and its `.status-name` (every other seat `data-role="none"`); `app.css` outlines them `2px solid #2dc653` (green) and `2px solid #f59e0b` (amber) with a subtle glow, with darker `#15803d` / `#b45309` variants under `html[data-theme='light']`. The right slot shows `DURAK` (`[data-testid="player-durak-tag-<id>"]`) for the last player out, otherwise `WINNER` / `OUT` from `finishRank`, otherwise `PASSED`. `durakId` comes from `resultView.durak`, else the sole seat missing from `winners` once `GameOver`, else the last entry of a `finishOrder` with at least two players (a lone entry is only the winner), and is `null` for a draw.
- **`GamePage` session chrome:** the header renders `Game {id}`, the connection state, a `POV` menu (`[data-testid="pov-menu"]`) listing every seat — opponents by `opponent.name`, the viewer by `view.myName`, then a `knownNamesRef` recorded from live views **and** replay frames, then the seat id as a last resort, so no seat is ever a bare `"You"` — and `Back to lobby`. `formatPlayerDisplayName(seatId, baseName, activePlayerId)` appends `' (You)'` to the active seat in the `POV` menu options, the left-sidebar `POV` tabs and the right-sidebar `PLAYERS` list (`[data-testid="players-list"]`, `.status-badge .status-name`), so switching POV moves the suffix to the newly active user. A `leaveGame` handler is shared by the header button, the `[data-testid="banner-lobby-button"]` (`Return to lobby`) inside the game-over banner, and the loading-state header, and calls the optional `onLeaveGame` prop (`App` passes `navigate('/')`) or `window.location.assign('/')`.
- **Rematch (ITEM-PB-9) & QA presets:** the game-over banner also renders `[data-testid="banner-rematch-button"]` (`Rematch`, disabled while creating). It rebuilds the match from the displayed projection — `playerCount`/seat order from `seatOrderedPlayerIds`, `playerNames` from `nameFor(id)` in `p0…pN` order, `allowRedirect`, `chaosMode` and per-seat `playerTypes` from `PlayerGameView` — calls `createGame(...)`, clears `view`/`replay`/`replayFrameIdx`/`selection` so the old finished match cannot leak into the new table, and opens the new `gameId` on the current seat through the optional `onNavigateGame(gameId, playerId)` prop or `window.location.hash = '#/g/<gameId>?player=<seat>'`. The left-sidebar (and lobby) `⚡ QA Scenarios` buttons call `createPresetGame(presetId)` and navigate to the returned `defaultPlayerId`, surfacing a failure in a small `role="alert"` line instead of navigating.
- **Bot POV input lock (ITEM-ADD-9):** `isBotViewer` is true when `view.isBot` or `view.playerTypes[viewerSeatIndex(view)]` names a non-human seat. It short-circuits `dispatch` (WebSocket **and** REST), disables the auto-surrender timer, hides the `Attack` / `Throw In` buttons and `ActionBar` (`isBotSeat`), and is passed to `GameTable` as `isBot`, which reports `data-bot-locked="true"` and treats the table as read-only exactly like review mode.
- **Replay review mode:** `isFinishedMatch(view, displayedView, replay, playerId)` treats a match as over when the authoritative `view`, the frame on screen, or the last recorded frame has a GameOver `boutPhase` (case/snake variants normalized by `normalizeToken`), so the `[data-testid="game-over-banner"]` always renders above the shell after the result and never disappears when the viewer steps back into an intermediate frame; its winner/Durak/finish order come from `view` while it is GameOver, otherwise from the final replay frame. The mount effect is keyed on `gameId` **and** `playerId`, but only a new `gameId` (`viewGameRef`) resets the table, the replay and `replayFrameIdx`; a `POV` switch keeps the mounted view and re-fetches just that seat's projection (`ITEM-PB-12a`). The replay itself is fetched by a separate effect keyed on `gameId` alone (plus the `gameOverPhase` fallback effect), so switching seats never refetches it and never jumps the reviewer back to the final move; the only initialisation to `visibleReplayFrames(replay).length - 1` happens when that match's recording first loads. If the REST view fails or the match is finished, the final frame (`frames[last].views[playerId] ?? frames[last].views[<first>]`) hydrates `view`, so opening a finished game's URL (`#/g/:gameId`, `#/g/:gameId/replay`) never stays on `Loading game`. A rejection falls back to the live view.
  - **Non-move filtering (`ITEM-PB-12c`):** `visibleReplayFrames(replay)` drops any frame whose `action.type` is `PassTurn` while `tablePairs`, `discardCount`, `talonCount` and `boutPhase` are unchanged from the previous frame (`isNonMoveFrame` compares a public signature), so `Move X / Y` only counts visible actions and `replayFrameIdx` indexes that filtered list.
  - **Replay sounds (`ITEM-PB-12b`):** `replayFrameSound(frames, targetIdx)` maps the target frame's recorded action to a `SoundEngine` call — `InitialAttack`/`ThrowInCards` → `playAttackCard` (or `playRedirect` when `attackerIdx` moved), `CoverCard` → `playDefendCard`, `RedirectAttack` → `playRedirect`, `DeclareSurrender` → `playSurrender`, a bout-ending `PassTurn` → `playTalonDraw` (else `playAttackCard`), and a GameOver frame → `playGameOver`. `playReplayFrameSound` runs inside `stepReplay(delta)`, which both the `‹`/`›` buttons and the `ArrowLeft`/`ArrowRight` handler use. `parsePlayerGameView` accepts the finished payload's nullable `turnPlayerId`/`turnDeadlineMs` (both `null` → idle) and the optional `winners`, `durak` and `promptedPlayerIds` fields; a rejected parse used to leave the loading state stuck forever. `displayedView` is `frames[idx].views[playerId] ?? frames[idx].views[<first>] ?? view` and drives `GameTable`, the hand, `TableDeck`, the `PLAYERS` list and the clocks. The `[data-testid="review-nav"]` panel under How to Play renders `[data-testid="review-prev-button"]` / `[data-testid="review-move-indicator"]` / `[data-testid="review-next-button"]`, clamped to `0 .. frames.length - 1` and disabled at the ends (or with no frames). A `window` `keydown` listener active only while review mode has frames steps `ArrowLeft`/`ArrowRight` backward/forward with the same clamping, calls `preventDefault()`, and ignores `Ctrl`/`Alt`/`Meta` chords and `<input>`/`<select>`/`<textarea>`/`contentEditable` targets. `formatGameClock(startedAtMs, endedAtMs, nowMs)` drives `[data-testid="game-clock"]`; in review it is `formatGameClock(0, activeFrame.elapsedMs, 0)`, because `GameReplay.frozenViews` sets `gameStartedAtMs = 0` / `gameEndedAtMs = elapsedMs`, and its `data-active` is `'true'` only while `!reviewMode && gameStartedAtMs != null && gameEndedAtMs == null`. The Game and Turn timers live in one `[data-testid="clock-panel"]` (`section.panel.clock-split-panel`) split into `.clock-half.game-clock-half` and `.clock-half.turn-clock-half` by a single divider. `passCountdownSeconds` (viewer on the pass clock) is still passed to `ActionBar`.
- **`TableDeck` discard pile:** `TableDeck` accepts `discardCount` and `lastDiscardCards` and builds one `discardFaces` row (`discardCount - lastDiscardCards.length` face-down `CardBack`s followed by the last bout face-up). There is **no discard counter or count badge**: `data-testid="discard-count"` / `.discard-count` no longer exist. The row is a `data-testid="discard-stack"` `.discard-stack` with `flex-wrap: nowrap`, `overflow: hidden`, `min-width: 0`, `max-width: 100%` and `box-sizing: border-box`, whose inner width is measured on the `[data-testid="discard-pile"]` box with a `ResizeObserver` (fallback `DISCARD_FALLBACK_WIDTH = 236`), and every slot's `marginLeft` comes from the same `handLayout` / `handMargins` pair the hand uses with the talon deck's measured width (`DECK_CARD_WIDTH = 80`). Cards are therefore deck-sized (`--deck-card-width` / `--deck-card-height`, `80×114`), surplus slots stack at 100% overlap with `data-hidden="true"`, and cursor movement over the row slides the hidden stack exactly like `.hand-cards`. `discardCount === 0` renders the `Empty` state instead.
- **`GameTable.tsx`** uses a 3-column x 3-row CSS Grid without freeform `position: absolute` layout:
  - **Row 1 (Clockwise Opponent Seats):** Computes relative seat offset `(seatIdx - myIdx + N) % N` to map opponents into `data-seat="top-left"`, `data-seat="top-center"`, and `data-seat="top-right"`. Each seat box centres its overlapping card backs (`.opponent-hand` is a `max-content` grid centred in the box) and carries the card count as an oval on the hand's top-left corner (`data-testid="opponent-card-count-<id>"`, `data-position="top-left"`); no `N cards` text is rendered.
  - **Row 2 (Defender-Anchored Battlefield):** Positions target outlines (`data-testid="target-outline-<playerId>"`), active `TablePair` cards, and the single-card SVG arrow reflection outline (`data-testid="redirect-outline"`) directly in front of the defending player's seat. The reflection outline is a sibling of the `TablePair`s inside `.table-pairs-group`, so all of them sit in one flex row: it uses `--bout-card-width` / `--bout-card-height`, `align-self: flex-start`, `box-sizing: border-box` and the same `--bout-card-offset` bottom reserve as `.table-pair`, keeping its top, centre and bottom edges vertically aligned with every card in play.
  - **Fixed play area, tight hand highlight & surrender shift:** `.battlefield-tinted-box` is one fixed box spanning row 2 at `88%` width, so its size never depends on the card count; `data-testid="hand-turn-highlight"` is the `.hand-cards` container itself (measured against the outer `[data-zone="player-hand"]` wrapper, `display: inline-flex`, `width: fit-content`, symmetric `4px` padding), so the glow encloses only rendered cards; the glow is active for the opening attacker **and** for every player holding a legal `ThrowInCards` action after the opening attack (`.hand-cards.throw-in-turn`), never suppressed by cards already on the table; and `.table-pairs-group[data-surrendered='true'][data-surrender-target='top-left'|'top-center'|'top-right'|'bottom']` applies a single `translate()` that slides the whole bout toward the surrendering seat while the tinted box stays put.
  - **Row 3 (Player Controls):** Places `[data-zone="player-hand"]` at `Col 2` and only the contextual `Surrender` / `Pass` button at `Col 3`. The talon no longer sits on the felt: `TableDeck` renders in `sidebar-right` as a `DECK`-titled box whose `.deck-assembly` (vertical deck, horizontal trump sharing one grid cell with left edges aligned, `TRUMP` badge below in normal flow) is centred as a block, with the deck count oval on the deck's top-left corner. The `SortBar` moved out of the arena into the `hand-sort-box` below the table; `GameTable` takes a `sortMode?: SortMode` prop (default `'suit'`) that only reorders the viewer's hand.

### 3.2 Header Bar, Settings Store & Appearance Subsystems
- **`HeaderBar.tsx`:** Owns the brand link (inline SVG mark followed by the `LIDURAK` wordmark inside one `<a class="header-brand">`), the hover navigation menus, and the profile dropdown with its live connection tracker.
  - **In-place submenus:** `PROFILE_ITEMS` marks four rows (`Sound`, `Theme`, `Table`, `Card Back`) with a `SubmenuId`. Selecting one swaps the main list for `<div class="profile-submenu-panel">`, whose first child is a `button.submenu-header[data-testid="submenu-back"]` holding a left chevron and `SUBMENU_LABELS[id]`; activating it clears the submenu state. The connection tracker stays pinned to the bottom of the panel in both modes.
  - **Connection tracker:** `connectionLevel(pingMs)` maps latency to a 1–4 bar tier (`≤60`, `≤150`, `≤300`, else `1`). Labels render `PING` / `SERVER DELAY` with a lowercase `ms` unit. A `useEffect` keyed on the tier sets `connection-bars-updating` for 360 ms only when the tier changes, so the bars animate on change and sit still otherwise. The active bars are coloured by tier — green (`#2dc653`) for `level >= 3`, yellow (`#eab308`) for `2`, red (`#ef4444`) for `1` — exposed as `data-bar-color` on `.signal-bars` and on every `.signal-bar[data-active]`, with matching rules in `app.css`. The tracker is driven directly by the measured `pingMs` prop (no manual override); the profile dropdown contains no lag-switch control.
  - **Live felt previews:** every `Table` swatch receives `backgroundColor`, `backgroundImage` and `filter` from `getTableFilterCss(...)`, so the brightness/contrast/hue sliders repaint previews and the table together.
  - **Sound previews:** pack buttons audition a random effect from the chosen pack immediately. The volume slider is silent while dragging (`onInput` only stores the level via `setVolume` / `soundEngine.setVolume` and repaints the `%` readout); `onPointerUp` / `onMouseUp` / `onTouchEnd` call `soundEngine.playSampleSound(undefined, volume)`, deduplicated by a ref flag reset on the next tick so one gesture plays exactly one sample at the released volume.
- **`state/settings.ts`:** Tiny observable store (`getSettings`, `setSettings`, `subscribeSettings`, `useSettings`, `resetSettings`). `applySettings` writes `data-theme`, `data-table-texture`, `data-card-back` and the `--app-roundness`, `--table-felt(-overlay)`, `--table-texture-bg(-overlay)`, `--table-brightness`, `--table-contrast`, `--table-hue` and `--table-filter` custom properties on `<html>`; `initSettings()` keeps `Device theme` in sync with `prefers-color-scheme`.
- **`styles/tableTextures.ts`:** `TABLE_TEXTURES` holds six presets (`emerald-felt` is `DEFAULT_TABLE_TEXTURE_ID`), each with a dark base colour and layered CSS overlay plus a pale `lightBase` / `lightOverlay` / `lightBorder` trio. `lightOverlay` mirrors its `overlay` layer for layer — same `repeating-linear-gradient` / `repeating-radial-gradient` / `radial-gradient` types, angles (`45deg`, `135deg`, `90deg`, `88deg`), positions and pattern frequencies — and swaps only the colour stops, so each felt shows the identical texture in both themes with only the palette differing; `table.css` repeats the same pairs as `--table-felt-overlay-light` for all six `[data-texture]` blocks. `textureFilter` / `getTableFilterCss` clamp and stringify `brightness() contrast() hue-rotate()`.
  - **Theme-calibrated absolute brightness (ITEM-PB-4):** `DEFAULT_TABLE_BRIGHTNESS = 100` keeps the Brightness slider at its `100%` default (`DEFAULT_TABLE_FILTERS.brightness = 1`) and `TABLE_BRIGHTNESS_SLIDER_MIN/MAX = 50/150` describe its range (`tableBrightnessPercent` / `tableBrightnessFromPercent` convert between the control and the stored multiplier). `DARK_MODE_BRIGHTNESS_FACTOR = 1.1` and `LIGHT_MODE_BRIGHTNESS_FACTOR = 0.9` scale that slider value in `absoluteTableBrightness` / `tableThemeBrightnessFactor`, so at slider `100` the dark felt paints at `brightness(1.10)` and the light felt at `brightness(0.90)` while both keep scaling proportionally as the slider moves. `textureFilter`, `getTableFilterCss` and `tableTextureStyle` / `getTableTextureStyle` all take an optional `theme` (`light` | `dark` | `device`, resolved by `resolveTableTheme`) and emit the calibrated value in `--table-brightness` and `--table-filter`, next to the raw slider multiplier (`--table-slider-brightness`) and the applied factor (`--table-theme-brightness-factor`). Because the shift is a filter factor rather than a palette swap, all six presets keep their dark surface distinctly darker (lower relative luminance) than their light surface. `resolveTableTheme(theme?, root?)` honours an explicit `light`/`dark`, resolves `device`/`undefined` from the applied `data-theme`, `tableTexturePalette(preset, theme)` picks the palette, and `tableTextureStyle` / `getTableTextureStyle` return the values plus both palettes as an inline style object (`--table-felt(-overlay)`, `--table-felt-light`, `--table-felt-overlay-light`, `--table-felt-border-light`, `--table-theme`). `getTableTextureStyle` accepts an optional `theme`, so callers that never pass one still follow the document theme.
- **`components/CardBack.tsx`:** `CARD_BACK_PATTERNS` holds the six monochrome pattern tiles, `COLORFUL_CARD_BACK_PATTERNS` the seven gradient designs, and `ALL_CARD_BACK_PATTERNS` drives the picker. Colourful backs render a three-stop `<linearGradient>` plus a motif tile (stripes, diamonds, rings, rays, sparkle, grid, waves); `CARD_BACK_LABELS` supplies display names. `CardBack` follows `settings.cardBack` when no `pattern` prop is given, so the header setting reaches every face-down card.
  - **Theme-adaptive monochrome backs:** `DARK_CARD_BACK_PALETTE` preserves the original charcoal frame/tile (`#262421`, stroke `#3a3733`) and `LIGHT_CARD_BACK_PALETTE` supplies the ivory/slate set (`#f1f5f9` frame, `#64748b` frame stroke, `#e2e8f0` tile, `#94a3b8` inner border, `#334155` / `#475569` pattern inks). `resolveCardBackTheme(theme, prefersDark?, root?)` returns an explicit `light`/`dark`, otherwise reads the `data-theme` already applied to `<html>`, then falls back to `prefers-color-scheme`; `PatternTile` takes the resulting palette so every stroke and fill flips together. `data-card-back-theme` is exposed on monochrome SVGs only, alongside `data-colorful="false"` / `data-colorful="true"`. Colourful designs always take their own `COLORFUL_DESIGNS` palette, so they render identically in both themes.
- **`app.css` (theme layer):** Dark tokens live on `:root`; `html[data-theme='light']` (plus a `prefers-color-scheme: light` fallback for `html:not([data-theme])`) redefines surfaces, panels, inputs, borders, text and accent colours. Lobby, game and panel rules consume `--app-panel`, `--app-input-bg`, `--app-border`, `--app-text` and `--app-text-strong` instead of hardcoded hex values, so every page, form, button and panel adapts to the chosen theme.
  - **Back to lobby contrast:** `.game-page .back-to-lobby` keeps the plain `.action-button` look in the dark theme (`padding: 8px 16px; font-size: 14px`). `html[data-theme='light'] .game-page .back-to-lobby` — and the `prefers-color-scheme` fallback for `html:not([data-theme])` — paints a `#e2e8f0` slate surface (hover `#cbd5e1`), a `1px solid #64748b` border (hover `#334155`) and `#0f172a` text at `font-weight: 600`, so the button stays legible on the pale game header.

### 3.3 Interaction & Web Audio Subsystems
- **Magnetic Drag-Snap & Double-Click:** Pointer drag handlers compute Euclidean distance to valid drop zones, snapping a preview highlight when within `48px`. Double-clicking a hand card evaluates all legal actions for that card and dispatches immediately if and only if exactly one target/action is legal.
- **`SoundEngine.ts`:** Synthesizes procedural sound effects via the browser Web Audio API (card slap thuds at distinct pitches for attack/cover/redirect/surrender, player-specific page-turn brushes on talon draw, 5-second clock warning ticks, and a Lichess-style two-note game-over chime). Five packs (`SOUND_PACKS`) each voice every `SoundEvent`; `playSampleSound(pack?, volume?)` previews a random effect from `SAMPLE_EVENTS`, optionally through a one-off preview gain bus at the supplied volume, without mutating the persisted pack or volume.

### 3.4 Card Rendering (`components/Card.tsx`)
- `Card.tsx` draws every face in an inline SVG `viewBox="0 0 70 100"`. Number ranks map to fixed pip tables; aces get one large ornate pip; `J`/`Q`/`K` render a center letter at `(35, 50)` with `dominant-baseline="central"`.
- **Face pips (`class="card-pip face-pip"`):** `judge`-style corner tables place pips at the ends of the letter — `jack` = 3 (`top-left`, `top-right`, `bottom-left`), `queen` = 1 (`bottom-right`), `king` = 4 (all corners). Each pip carries `data-corner`, `data-rotation`, and `transform="rotate(angle x y)"`.
- **Reserved corner index (`CARD_INDEX`):** the top-left rank text sits at `(5, 21)` with a 15pt font and the corner suit glyph at `(4, 34)`; the bottom-right pair is mirrored at `(65, 95)` / `(65, 82)`. `PIP_LAYOUTS` place every number-card pip in columns `x = 22`, `x = 35`, `x = 48` with rows from `y = 33` to `y = 78`, so the wide two-digit `10` rank text, the corner suit and the top-right trump badge at `(61, 10)` with `r = 6` are strictly disjoint from every pip (including the 2×4 + 2-centre `10` layout). `PIP_FONT_SIZE = 12` and `ACE_PIP = { x: 35, y: 58, fontSize: 40 }` keep the glyphs clear of those bands as well.
- **Theme-dependent card front:** `cardFrontPalette(theme)` returns `LIGHT_CARD_FRONT_PALETTE` (`face: #ffffff`, border `#bababa`) or `DARK_CARD_FRONT_PALETTE` (`face: #cbd5e1`, border `#94a3b8`). `resolveCardFrontTheme(theme, prefersDark?, root?)` honours an explicit `light`/`dark`, otherwise reads the `data-theme` written to `<html>` by `settings.ts`, then falls back to `prefers-color-scheme`; `useCardFrontTheme` re-renders `Device theme` cards when the OS scheme changes. The resolved palette fills both the SVG face `<rect>` and `data-card-face`, and `data-card-theme="light" | "dark"` is exposed on the card wrapper and the SVG for CSS and tests.
- **Outward rotation:** `facePipAngle(suit, corner)` returns `-45` / `45` / `135` / `-135` for hearts & clubs (distinguishing top half faces out) and the 180-degree opposite set (`135` / `-135` / `-45` / `45`) for spades & diamonds (bottom half faces out).
- **Trump marker:** the gold badge is a `circle` at `(61, 10)` with `r=6` and an 8pt suit glyph (≈13.7px on an 80px card), so it sits inside the rounded top-right corner and never intersects the rank pips, the ornate ace pip or the face letter.

### 3.5 REST & WebSocket Client (`api/`)
- **`client.ts`:**
  - `createGame(playerCount, playerNames, allowRedirect, chaosMode, playerTypes?)` → `POST /api/game/create`; `playerTypes` is `readonly PlayerType[]` (`'human' | 'randomBot' | 'basicBot'` per seat) and defaults to all `'human'`.
  - `checkServerHealth()` → `GET /api/health`, resolving `true` for a 2xx response and `false` for any error, so the lobby can poll backend readiness.
  - `getGameView()` and `sendAction()` validate every payload with `parsePlayerGameView`.
  - `getGameReplay(gameId)` → `GET /api/games/:gameId/replay`, validated by `parseGameReplay` (`ReplayFrame`, `RecordedMove`, `GameReplay` in `types.ts`); each frame's `views` go through `parsePlayerGameView`, so replay mode consumes the same trusted projection as the live table.
- **`websocket.ts` (`GameWebSocket`):**
  - Validates each frame through `parsePlayerGameView` and ignores control/malformed frames (`{"type":"pong"}`, bare pings, empty payloads) without touching UI state.
  - Sends `{"type":"ping"}` every `20_000ms` while `OPEN` as an application-level heartbeat (the server also pushes a WebSocket `Ping` every 20 s and now allows a 10-minute idle timeout instead of Ember's 60-second default); the timer is cleared on close and `disconnect()`.
  - `sendPresence(isPresent)` emits `{"type":"presence", isPresent}`, queues the latest value until `onopen`, and re-sends it after an automatic reconnect.
  - Reconnects with 1s/2s/4s exponential backoff, at most three retries.
- **`types.ts` presence fields:** `PlayerType = 'human' | 'randomBot' | 'basicBot'`; `PublicPlayerSummary.isPresent` and `PlayerGameView.presentPlayers` are optional, validated by the parser when present.

### 3.6 Hand Layout, Felt Filters & Presence
- **Hand geometry (`GameTable.tsx`):** `handLayout(count, availableWidth, cursorFraction, cardWidth)` returns `{ overlap, visibleCount, hiddenLeft, hiddenRight }`. Overlap starts at `HAND_MIN_OVERLAP = 8px` and tightens only up to `cardWidth - max(12px, 28% of the card width)`, so the top-left rank/suit index stays readable; past that capacity the surplus stacks at 100% overlap on the ends. `handMargins()` turns the layout into per-slot negative margins, `.hand-slot[data-hidden='true']` drops behind the visible row (`z-index: 0`, no pointer events), and pointer movement across `.hand-cards` moves cards between the hidden left/right stacks. `handOffsets()`/`handMargins()` never wrap: `.hand-cards` is `flex-wrap: nowrap`. Opponent seats use `opponentOverlap()` inside a fixed `208×32` row that reacts only to card count. Widths are measured with a `ResizeObserver` on the hand column, falling back to `HAND_FALLBACK_WIDTH` when layout is unavailable.
- **Felt layer:** the arena carries `data-texture` plus `--table-filter` from `useSettings()`, and `[data-zone='table-arena']::before` paints `--table-felt`/`--table-felt-overlay` across the whole grid while `filter: var(--table-filter)` applies brightness/contrast/hue to the surface only — cards stay untinted and match the header's live previews.
- **Theme-dependent felt (`table.css`):** every `[data-texture='…']` block also declares `--table-felt-light`, `--table-felt-overlay-light` and `--table-felt-border-light` (the pale sage/navy/rose/slate/olive/sand variants). A `:root[data-theme='light'] [data-zone='table-arena']` rule remaps `--table-felt`/`--table-felt-overlay` to those light values and adds a `lightBorder` inset frame on `::before`, so switching the theme repaints the felt with no `GameTable`/`GamePage` change. The same light block pales `.seat-box`, `.battlefield-tinted-box`, `.target-outline`, `.redirect-outline`, `.talon-count`/`.deck-count-badge`, `.trump-badge` and `.sort-select`, darkens their text to `#0f172a`/`#1e293b`, and veils `.texture-swatch` previews (whose background is inline) with an inset white shadow.
- **Trump placement:** `.table-trump-card` uses `transform: translate(8px, -6px) rotate(90deg)` (5px/-4px on small screens), so the horizontal trump tucks under the vertical talon instead of overflowing its left/bottom edges.
- **Presence:** `GamePage` tracks `document.hasFocus()` plus 30-second mouse/keyboard activity (`PRESENCE_IDLE_MS`), reports changes through `GameWebSocket.sendPresence`, and renders `presence-dot` in every `PLAYERS` row from `PlayerGameView.presentPlayers`, `PublicPlayerSummary.isPresent`, or the local activity state for the viewer. Dots are green (`--durak-accent`) when present and grey otherwise.
- **Frozen clocks:** `viewerOnClock` compares `turnPlayerId` with `myId`; the right-sidebar clock renders `00:15` with `data-active="false"` unless the viewer is the timed player, while each seat and hand clock shows its own player's remaining seconds.
### 3.7 Lobby Readiness & Seat Types (`pages/LobbyPage.tsx`, `app.tsx`)
- **App shell:** `App` renders `<HeaderBar />` directly above the routed page with no `<h1 class="app-title">` — the `LIDURAK` brand link already titles every page, so the duplicate heading is gone.
- **Readiness gate:** `LobbyPage` probes `checkServerHealth()` (i.e. `GET /api/health`) on mount and then every `1000 ms` until it succeeds. While the backend is not ready it renders the themed `.server-loading-page` block (`data-testid="server-loading"`, `role="status"`, message `Starting game server, please wait…`) containing the `.lobby-loading-spinner` ring (`data-testid="lobby-loading-spinner"`) — a circular border with a high-contrast accent top/right segment animated by the `lidurak-spin` keyframes (0.85 s linear, infinite) in `app.css` — instead of the form, so no click can reach a proxy `HTTP 500`; the poll unlocks the form on its own once the server answers.
- **Warm-up recovery:** a `createGame(...)` failure that looks like a booting backend — an `HTTP 500` / `502` / `503` / `504` message or a `TypeError` from `fetch` — drops the lobby back into the loading state and re-polls instead of showing an error banner. Any other failure (for example an unsupported player count) still renders `.error-banner`.
- **`initialServerReady?: boolean` prop:** starts the lobby unlocked and skips the probe; tests and caller-known server state use it, the app itself leaves it unset.
- **Seat types:** `playerTypes` state mirrors the seats (`['human', 'human']` initially), stays length-matched when the count changes and preserves earlier choices, and is passed as the fifth `createGame(...)` argument. Every player row renders its name `<input>` plus a `<select data-testid="player-type-<index>" aria-label="Player <n> type">` offering `Human` / `RandomBot` / `BasicBot` in that order (`human` / `randomBot` / `basicBot` values, matching the backend's canonical `GameConfig.playerTypes`); the state is typed `PlayerType[]`.
- **Theming:** every lobby element uses the shared token-driven classes (`lobby-form`, `field`, `name-fields`, `checkbox-field`, `.server-loading-page`, `created-game`, `player-tabs`, `error-banner`), so the Create a Game page follows `html[data-theme='light']` without page-specific colour overrides.
