## 2. Backend Architecture (`backend/src/main/scala/durak/`)

### 2.1 Pure Game Engine (`durak.engine`)
All core rules reside in side-effect-free Scala 3 case classes and enums:
- **`Card`, `Suit`, `Rank`:** Models suits (`Clubs`, `Diamonds`, `Hearts`, `Spades`) and ranks (`Two` through `Ace`, supporting 36-card decks for 2–3 players and 52-card decks for 4 players).
- **`GameConfig`:** Stores `playerCount`, `allowRedirect`, `seed`, `chaosMode` (target-aware opening attacks and redirects; see below) and `playerTypes` (per-seat `"human"` / `"randomBot"` / `"basicBot"`; any seat the vector does not name is human). `config.seatType(idx)` returns the canonical seat type (`GameConfig.HumanSeat`, `RandomBotSeat`, `BasicBotSeat`), `config.isBotSeat(idx)` is true for both bot kinds, `GameConfig.canonicalSeatType` maps accepted spellings (case/padding-insensitive, with `"bot"` as the random shorthand) and falls back to a human seat for unknown values, and `GameConfig.normalizePlayerTypes(playerCount, types)` pads/truncates and canonicalizes a request's seat list.
- **`GameState` & `BoutPhase`:**
  - Tracks `players: Vector[PlayerState]`, `talon: Vector[Card]`, `bottomTrumpCard: Option[Card]`, `trumpSuit: Suit`, `discardPile: Vector[Card]`, `tablePairs: Vector[TablePair]`, `attackerIdx: Int`, `defenderIdx: Int`, `boutPhase: BoutPhase`, `winners: Vector[String]`, `durak: Option[String]`, and `presentPlayers: Set[String]` (human seats that reported an open connection). Presence is derived through `isPresentSeat(idx)` / `isPlayerPresent(id)` / `presentPlayerIds`, and bot seats are always present.
  - **Card Conservation Invariant:** Across all transitions (`InitialAttack`, `CoverCard`, `RedirectAttack`, `ThrowInCards`, `DeclareSurrender`, `PassTurn`, and bout resolution draws), total cards across `talon + discardPile + hands + tablePairs` remains strictly constant (`36` or `52`).
  - **Last-Player-Standing Victory:** Players who empty their hands once `talon.isEmpty` are appended to `winners` in order of finish and skipped by clockwise turn helpers (`nextActivePlayer`). Play continues until `activePlayersWithCards.size <= 1`, designating the final remaining player holding cards as `durak`.
  - **Chaos Mode (`GameConfig.chaosMode`, fully implemented in the engine):** `GameAction.InitialAttack(playerId, cards, targetPlayerId: Option[String])` carries the chosen opening target. In a standard game any target other than the clockwise `defenderIdx` is rejected; in Chaos mode the target must appear in `GameEngine.eligibleInitialTargets` (every other seat that still holds cards, in clockwise order from the attacker; empty outside `InitialAttack`), and an empty target falls back to the seat that is already the defender. Naming a different defender rewrites `defenderIdx` and `defenderInitialHandSize` for that seat exactly as a redirect does, and the attacker can never become its own defender.
  - **`GameEngine.eligibleRedirectTargets` / `deterministicRedirectTarget`:** eligible receivers are every other active seat holding at least `tablePairs.size + 1` cards. A standard game yields only the next active clockwise seat; Chaos mode yields every eligible seat, which is what the reflected-arrow outline shows. `deterministicRedirectTarget(state, extraCards = 1)` picks the Chaos receiver with a `Random` seeded from the game seed plus the talon, discard and table sizes, so `applyAction` stays pure and a replay reproduces the same redirect; `PlayerGameView.redirectTargetId` exposes that pick to the table.
  - **Delayed auto-pass on surrender (`GameEngine.playersNeedingAutoPass` / `autoPassSurrenderThrowers` / `canPlayerThrowIn`, ITEM-PREV-4b):** the engine never passes a thrower inside the transition that opens the window. `DeclareSurrender` moves to `BoutPhase.SurrenderThrowIn` with `hasPassed = false` for every active non-defender that still holds cards (only a seat left with `0` cards is settled immediately), and a throw-in during that phase re-opens the window the same way. `playersNeedingAutoPass(state)` lists the active non-defenders with `hand.nonEmpty && !hasPassed && !canPlayerThrowIn` whenever `GameState.isThrowInPhase` holds — the surrender phase, or a `BoutPhase.Defense` whose attacking cards are all covered — and `GameActor` passes exactly those seats after its `noThrowInAutoPassDelay` (`1.second`). `PassTurn` is legal for any unpassed non-defender holding cards during `SurrenderThrowIn` (so `"pass"` appears in `legalActions` even without `"throwIn"`, and `promptedPlayerIds` lists every such seat), `resolveSurrenderBout` resolves the bout only once every active non-defender has passed, and `autoPassSurrenderThrowers` remains the delayed settlement step (it marks every seat that cannot throw in and then resolves).
  - **`GameReplay` non-move filtering:** `appendMove(replay, action, next, now, visible)` only records a replay frame when `GameReplay.isVisibleMove` is true. A `PassTurn` that leaves `tablePairs` and `boutPhase` unchanged (a thrower passing after a surrender) is a non-move: it is kept in `skippedMoves` so `verifyReplay` can still re-derive the game, but it never becomes a replay step, so every `Move X / Y` is a visible action on the felt.

### 2.2 Anti-Cheat State Projection (`PlayerGameView`)
- `PlayerGameView.forViewer(state, viewerId)` strips all hidden information before serialization.
- A connected client receives only their own `myId` and `myName` (their display name, `""` when an older payload omits it; encoded as `"myName"` and decoded with an `Option[String].map(_.getOrElse(""))` fallback) plus `myHand: Vector[Card]`, public summaries for opponents (`id`, `name`, `cardCount`, `hasPassed`, `finishRank`, `isPresent`), `talonCount`, `bottomTrumpCard`, `trumpSuit`, `tablePairs`, `legalActions`, `turnDeadlineMs`, and `presentPlayers` (ids of every present seat, in seat order) so the UI can draw green/grey presence dots. It also carries `promptedPlayerIds`, the discard summary (`discardCount` plus `lastDiscardCards`, the revealed top of the pile) and the overall clock (`gameStartedAtMs`, `gameEndedAtMs`, which freezes once the game ends). The table's own configuration and Chaos targeting travel with the view too: `isBot` (true for a computer-controlled viewer, whose `legalActions` is then empty), `playerTypes` (canonical `human` / `randomBot` / `basicBot` per seat, so a rematch can reseat them), `allowRedirect`, `chaosMode`, `eligibleTargetIds` (seats allowed by `GameEngine.eligibleInitialTargets`, populated only during `InitialAttack`) and `redirectTargetId` (the seat a redirect would land on — `eligibleRedirectTargets.headOption` normally, `deterministicRedirectTarget` in Chaos mode; empty when no redirect is on offer).
- **Finished-game projection (`boutPhase == GameOver`):** `forViewer` is total for every valid seat (`p0..pN`) and for a draw in which all hands are empty: the clock is idle (`turnPlayerId = None`, `turnDeadlineMs = 0`, `turnSecondsRemaining = 0`, even if the caller's state still carries a deadline), `legalActions` and `promptedPlayerIds` are empty, `gameEndedAtMs` is populated, and `winners` / `durak` come from `finishOrder`.
- **Own status projection (`myHasPassed` / `myFinishRank`, ITEM-ADD-8a / ITEM-ADD-8b):** the view carries the viewer's own pass flag (`myHasPassed = viewerState.hasPassed`) and finishing rank, encoded as `"myHasPassed"` / `"myFinishRank"` and decoded with a `false` / `None` fallback so older payloads still parse. Both the viewer's `myFinishRank` and every opponent's `finishRank` come from `PlayerGameView.finishRankFor`: the seat's position in `finishOrder` (1-based) **only when its hand is empty**, and `None` otherwise — a player holding cards is never projected as finished, whatever a stale `PlayerState.finishRank` says. Together they let the frontend `PLAYERS` list label the active user (`Alice (You)`) with `WINNER` / `OUT` / `PASSED` exactly like the opponents.
- **QA preset positions:** `surrender-half-off` is a three-player `BoutPhase.Defense` on Bob (`p1`, `defaultPlayerId`) — `7♠` uncovered plus two covered pairs, `trumpSuit = ♣`, Bob holding no trump at all and no spade above the `7♠` (so `defenderDefenseless = true` and `legalActions = ["surrender"]`, with the discard pile's `10♦` swapped in for the old `9♠` so all 36 cards stay unique), Carol holding no `6`/`7`/`8`/`9`/`J` (so `GameEngine.canPlayerThrowIn(state, 2) == false` and the 1-second delayed auto-pass marks her `PASSED`) and Alice holding `7♥` so the surrender lands in `SurrenderThrowIn` and waits on her 15-second clock. `discard-and-endgame` is a three-player `SurrenderThrowIn` with an empty talon, Carol (`p2`) already out on `0` cards (`finishOrder = ["p2"]`), Bob (`p1`) holding `3` cards with no finishing rank, Alice (`p0`, `defaultPlayerId`) holding `7♥` against the `7♠` on the felt and a 31-card discard pile whose last four cards are revealed; Alice's single throw-in leaves her on `0` cards and the delayed auto-pass settles the surrender, eliminating her (`OUT`, rank 2) and crowning Bob `DURAK`. `defenseless-surrender` is the same three-player `Defense` shape on Bob (`p1`, `defaultPlayerId`), but Alice attacks with `J♠` while Bob holds `9♠` (same suit, lower rank) and off-suit hearts, so `legalActions = [surrender]`, `defenderDefenseless = true` and the client arms `CLIENT_AUTO_SURRENDER_DELAY_MS` from the first frame — the minimal one-click demo for T-90 ITEM-PREV-4a, while `surrender-half-off` adds the half-off surrendered cards and the server auto-pass. Both presets open on Bob's own POV, where T-90-2 ITEM-PREV-4 keeps the crimson defender glow on the tight `.hand-cards` box (`data-highlighted="true"`, `data-highlight-variant="defender"`, `data-defenseless="true"`) for the whole countdown until the surrender is pressed or fires, then switches to `data-highlighted="false"` / `data-highlight-variant="none"` / `data-surrendering="true"` once the phase is `SurrenderThrowIn`; switching `POV` to Alice (`p0`) during the throw-in restores the normal amber throw-in glow because her `7♥` is a legal `throwIn`. All three positions keep the 36-card conservation invariant across hands + table + talon + discard.
- **Throw-in projection:** during `BoutPhase.Defense` a non-defender holding a card that matches a rank on the table already receives `"throwIn"` in `legalActions` while the attack is still uncovered — the defender keeps the turn clock until every attack is covered. Once the table is covered or the defender has surrendered, every eligible thrower is additionally listed in `promptedPlayerIds`, so only they (and never the surrendered defender) hold the clock.

### 2.3 Concurrent Server Actors & Turn Clock (`durak.server`)
- **`GameActor`:** Wraps each match's `GameState` in a `Cats Effect` `Ref[IO, ...]` and broadcasts personalized `PlayerGameView` snapshots over a `Topic[IO, ...]` to connected WebSocket clients. `setPresence(room, playerId, isPresent)` stores presence in the state and re-publishes it whenever the value changes, so presence dots update without anyone having to play a move. `GameActor.submitClientAction(room, action)` is the single entry point for REST and WebSocket moves: it rejects any action naming a `config.isBotSeat` seat with `GameActor.BotSeatInputError` (`"Cannot submit user input for a bot player"`) before the action can reach the engine, so a client can never play for a bot — only the room's own bot driver writes those seats.
- **Bot seats (`engine/RandomBot`, `engine/BasicBot` + `GameActor.startBots`):**
  - `RandomBot.legalActionsFor(state, playerId)` enumerates opening attacks (every hand card), covers, redirects, surrenders, throw-ins and passes for the seat's role and phase, then keeps only the actions `GameEngine.applyAction(state, playerId, action)` accepts; a finished seat and a surrendering defender get nothing. `RandomBot.chooseAction(state, playerId, rng)` picks one uniformly.
  - `BasicBot.legalActionsFor` delegates to `RandomBot`, so both bots share one engine-filtered move set. `BasicBot.chooseAction` applies a fixed policy: the lowest-ranked non-trump opening attack (a uniformly random trump when the hand holds only trumps), the cheapest non-trump cover/redirect whenever one is legal (surrendering only when none exists), and the lowest non-trump throw-ins — never a trump throw-in, passing once only trumps remain.
  - `GameActor.chooseBotAction(state, botId, rng)` dispatches on `config.seatType`: `BasicBot` for a `"basicBot"` seat, `RandomBot` otherwise.
  - **Strict legal-move invariants (`GameEngine`):** `applyAction(state, playerId, action)` rejects a move issued by another seat (`GameEngine.actorId` names that seat), and `legalActions` filters every candidate through the same guard. `RedirectAttack` requires `allowRedirect`, an uncovered table under the 6-card cap, a matching-rank card in the defender's hand, `nextActivePlayerIdx(defenderIdx) != defenderIdx`, and a next defender holding at least `tablePairs.size + 1` cards — so a cardless opponent (for example one that attacked with its last card) can never become the defender. `CoverCard` and `DeclareSurrender` are defender-only and rejected during `InitialAttack`, `SurrenderThrowIn` and `GameOver`; a seat that is both attacker and defender can never cover its own attack, and during `SurrenderThrowIn` the surrendered defender has no legal action at all.
  - One driver fiber per room (started only when a seat is a bot) submits the chosen move through the same `applyAction` pipeline as a client, so clock restarts, validation, replay recording and broadcasts are shared. `GameActor.botDelayFor(room, state, botId)` decides the pace from `config.seatType(seat)`: a `GameConfig.RandomBotSeat` plays with **`0.millis`** delay (`None`; the loop `IO.cede`s first so fiber scheduling stays fair and HTTP/WebSocket handlers are never starved during an all-`RandomBot` game), while a `GameConfig.BasicBotSeat` keeps the random **`500.millis`–`2000.millis`** window — constructor-overridable for fast tests, but the default stays in that range. The pause races a state-change watch, so a move for a superseded position is dropped instead of played.
  - **`BoutPhase.GameOver` broadcast & replay guarantees:** whichever move reaches `BoutPhase.GameOver` (human, instant `RandomBot`, `BasicBot` or turn-clock auto-action) goes through the same pipeline, which stamps `gameEndedAtMs`, clears the turn deadline, appends the final frame with one frozen `PlayerGameView` per seat to the room's `GameReplay` and publishes the state to the `Topic` — so every connected socket receives the `GameOver` projection immediately. `GameManager` never evicts a room, so `GET /api/games/:gameId/view`, `GET /api/games/:gameId/replay` and `/ws/game/:gameId/:playerId` keep serving a finished match instead of 404-ing or hanging.
  - The prompted seat is the attacker during `InitialAttack`, the defender while an attack is uncovered, and otherwise any un-passed thrower — the same ordering the turn clock uses. Human seats are only ever animated by the turn clock.
- **Delayed auto-pass driver (`GameActor.startAutoPass` / `autoPassLoop` / `applyAutoPasses`, ITEM-PREV-4b):** every room starts one fiber that watches `GameEngine.playersNeedingAutoPass(state)`. While the list is empty it waits for the next state change; as soon as it is non-empty it sleeps `room.noThrowInAutoPassDelay` (`GameActor.DefaultNoThrowInAutoPassDelay = 1.second`, overridable through `GameActor.create` / `createFrom(noThrowInAutoPassDelay = …)`), racing a state-change watch so a surrender, a throw-in or a manual pass restarts the wait against the fresh position. On expiry it calls `applyAutoPasses`, which submits `GameAction.PassTurn(pid)` for each still-waiting seat through the normal action pipeline — so the turn deadline restarts, a pass that settles the bout becomes a visible replay frame, and the new state is published to the `Topic`. This keeps a surrendered bout in `SurrenderThrowIn` (cards half-off the felt) for one second and marks `PASSED` seats such as Carol in the `surrender-half-off` preset.
- **15-Second Turn Clock & 3-Second Auto-Action Delay:**
  - Every valid state transition resets `turnDeadlineMs = now + 15000`.
  - Background fibers monitor the turn deadline and execute the default timeout move (`InitialAttack` with a random card, `DeclareSurrender` for a defender, or `PassTurn` for a thrower) if 15 seconds elapse without input.
  - Forced automatic actions wait 3 seconds before firing so players can visually read the table state.
- **`GameRoutes`:**
  - `GET /api/health`: Readiness probe returning `200 {"status":"ok"}`; the frontend polls it before offering game creation.
  - `POST /api/games` (alias `POST /api/game/create`): Creates a match with `playerCount`, `playerNames`, `allowRedirect`, and `playerTypes` (`"human"` / `"randomBot"` / `"basicBot"` per seat, canonicalized to exactly `playerCount` entries). The response is `{ gameId, players, playerTypes }`.
  - `GET /api/games/:gameId/view?player=:playerId` (alias `GET /api/game/:gameId/view/:playerId`): Returns that seat's `PlayerGameView` JSON. An omitted or blank `player` falls back to `p0` (`GameRoutes.DefaultViewerId`), so a bare game URL always renders a finished table; only a non-blank id that names no seat is a `404`.
  - `POST /api/games/:gameId/action` (alias `POST /api/game/:gameId/action`): Submits a `GameAction` for a player. The action goes through `GameActor.submitClientAction`, so a bot seat is rejected.
  - `POST /api/games/preset`: Body `{ "preset": "<id>" }` starts one of `GameManager.Presets` (`3p-redirect-bob`, `chaos-4p`, `surrender-half-off`, `defenseless-surrender`, `discard-and-endgame`) as a fully spelled-out position in a fresh room, and returns `{ gameId, players, playerTypes, defaultPlayerId }` where `defaultPlayerId` is the seat that makes the scenario readable. An unknown preset is a `400` naming the valid ids. This is what the lobby and left-sidebar `⚡ QA Scenarios` buttons call.
  - `POST /api/games/:gameId/presence`: Body `{ "playerId": "p0", "isPresent": true }` (an `"active"` flag is also accepted) records human presence and returns that seat's view.
  - `GET /api/games/:gameId/replay` (alias `GET /api/game/:gameId/replay`): the recorded match — `gameId`, `moves` with their `elapsedMs`, and `frames` whose `views` hold one frozen `PlayerGameView` per seat, so a review viewer never needs the live room.
  - `GET /ws/game/:gameId/:playerId`: Bi-directional WebSocket streaming `PlayerGameView` updates. Text frames are `{"type":"ping"}`, `{"type":"presence","isPresent":…}` or a `GameAction`; incoming `Ping` / `Pong` frames are ignored silently. Opening the socket marks the seat present and closing it marks it absent.
  - **Keepalive & idle timeout:** the outbound stream merges a `WebSocketFrame.Ping()` every `20 s`, and `Main` raises Ember's idle timeout to `10 minutes` (from the 60-second default), which is what stopped idle tables from dying with `java.util.concurrent.TimeoutException`.

## 3. Frontend Architecture (`frontend/src/`)

### 3.1 Lichess 3-Column Shell & Deterministic 3x3 Table Grid
- **`GamePage.tsx`** renders three non-overlapping top-level CSS Grid columns:
  1. `[data-zone="sidebar-left"]`: `POV` player-switcher tabs (real player names), the `⚡ QA Scenarios` preset buttons (`[data-testid="qa-scenarios"]`, `QA_SCENARIOS` → `createPresetGame`), the How-to-Play reference card, and the replay move-navigation panel once a match is over.
  2. `.table-column`: a flex column holding `[data-zone="table-arena"]` (the central felt table, `GameTable.tsx`) on top and the `HAND SORTING` box (`[data-zone="hand-sort-box"]`, `data-testid="hand-sort-box"`, class `sidebar-box sidebar-sort-box hand-sort-box`) directly below it with a fixed `gap`, so the two can never overlap. `GamePage` owns the `sortMode` state (`'suit'` default) and passes it to both the `SortBar` in that box and `GameTable`.
  3. `[data-zone="sidebar-right"]`: the overall game clock (`mm:ss`, `[data-testid="game-clock"]`), the monospace digital turn clock (`00:XX`), the `PLAYERS` list with presence dots and attacker/defender outlines, the `TableDeck` (`DECK` title + centred talon/horizontal trump/`TRUMP` assembly with a top-left counter oval, plus the discard pile), and the match winner/Durak badges. The right column no longer holds the sort control (ITEM-ADD-7).
- **`PLAYERS` list structure (ITEM-ADD-2 / ITEM-ADD-8a / ITEM-ADD-8b):** every `.status-badge` row is a three-track CSS Grid (`grid-template-columns: minmax(0, 1fr) auto minmax(0, 1fr)`): left `.status-player` (presence dot + `.status-name`, `justify-self: start`), centre `.status-cards` (`${cardCount} cards`, `justify-self: center; text-align: center`) and right `.status-state-slot` (`justify-self: end`). The equal `1fr` side tracks pin the card count to the row's midpoint, so it never moves when a tag appears. While `displayedView.boutPhase` is not `GameOver`, the seat at `attackerIdx` gets `data-role="attacker"` and the seat at `defenderIdx` gets `data-role="defender"` on the `<li>` only (every other seat `data-role="none"`); the `.status-name` carries no role styling at all (`border: none; outline: none; box-shadow: none`, ITEM-ADD-2a). `app.css` gives the role row a soft diffused glow instead of a sharp outline (ITEM-ADD-2b): `outline: none`, a translucent `1px solid var(--role-attacker-border)` / `var(--role-defender-border)` border and a multi-layer `box-shadow` built from `var(--role-attacker-glow)` / `var(--role-defender-glow)` plus the matching inset surface tint. Under `html[data-theme='light']` (T-90) the same rows keep the diffused shape and use the same variables, which resolve to the darker, higher-alpha values: emerald `rgba(15, 118, 54, 0.88)` / `rgba(21, 128, 61, 0.78)` for the attacker and crimson `rgba(185, 28, 28, 0.9)` / `rgba(185, 28, 28, 0.78)` for the defender. The right slot wraps every label in `[data-testid="player-status-tag-<id>"]` (`data-status` names it): `DURAK` (`[data-testid="player-durak-tag-<id>"]`) for the last player out, otherwise `WINNER` / `OUT` from `finishRank`, otherwise `PASSED`. `WINNER` / `OUT` are strictly gated on `cardCount === 0` (ITEM-ADD-8b), so a seat still holding cards is never labelled finished even with a stale `finishRank` or `winners` entry. The active user's own row reads `displayedView.myFinishRank` and `displayedView.myHasPassed` instead of an opponent summary, so the viewer is labelled identically to everyone else (ITEM-ADD-8a / ITEM-ADD-8b). `durakId` comes from `resultView.durak`, else the sole seat missing from `winners` once `GameOver`, else the last entry of a `finishOrder` with at least two players (a lone entry is only the winner), and is `null` for a draw.
- **`GamePage` session chrome:** the header renders `Game {id}`, the connection state, a `POV` menu (`[data-testid="pov-menu"]`) listing every seat — opponents by `opponent.name`, the viewer by `view.myName`, then a `knownNamesRef` recorded from live views **and** replay frames, then the seat id as a last resort, so no seat is ever a bare `"You"` — and `Back to lobby`. `formatPlayerDisplayName(seatId, baseName, activePlayerId)` appends `' (You)'` to the active seat in the `POV` menu options, the left-sidebar `POV` tabs and the right-sidebar `PLAYERS` list (`[data-testid="players-list"]`, `.status-badge .status-name`), so switching POV moves the suffix to the newly active user. A `leaveGame` handler is shared by the header button, the `[data-testid="banner-lobby-button"]` (`Return to lobby`) inside the game-over banner, and the loading-state header, and calls the optional `onLeaveGame` prop (`App` passes `navigate('/')`) or `window.location.assign('/')`.
- **Rematch (ITEM-PB-9) & QA presets:** the game-over banner also renders `[data-testid="banner-rematch-button"]` (`Rematch`, disabled while creating). It rebuilds the match from the displayed projection — `playerCount`/seat order from `seatOrderedPlayerIds`, `playerNames` from `nameFor(id)` in `p0…pN` order, `allowRedirect`, `chaosMode` and per-seat `playerTypes` from `PlayerGameView` — calls `createGame(...)`, clears `view`/`replay`/`replayFrameIdx`/`selection` so the old finished match cannot leak into the new table, and opens the new `gameId` on the current seat through the optional `onNavigateGame(gameId, playerId)` prop or `window.location.hash = '#/g/<gameId>?player=<seat>'`. The left-sidebar (and lobby) `⚡ QA Scenarios` buttons call `createPresetGame(presetId)` and navigate to the returned `defaultPlayerId`, surfacing a failure in a small `role="alert"` line instead of navigating.
- **Bot POV input lock (ITEM-ADD-9):** `isBotViewer` is true when `view.isBot` or `view.playerTypes[viewerSeatIndex(view)]` names a non-human seat. It short-circuits `dispatch` (WebSocket **and** REST), hides the `Attack` / `Throw In` buttons and `ActionBar` (`isBotSeat`), and is passed to `GameTable` as `isBot`, which reports `data-bot-locked="true"` and treats the table as read-only exactly like review mode.
- **Client-side auto-surrender & auto-pass delays (T-90 ITEM-PREV-4a / ITEM-PREV-4b):** `GamePage` exports `CLIENT_AUTO_SURRENDER_DELAY_MS = 3000` and `CLIENT_AUTO_PASS_DELAY_MS = 1000`. `isClientAutoSurrenderState(view)` matches a human (`!isBotViewer`), live (`!reviewMode`) `Defense` projection whose `legalActions` contain `surrender` and neither `cover` nor `redirect` (or whose `defenderDefenseless` is true); `isClientAutoPassState(view)` matches `pass` without `throwIn` and `!myHasPassed` in `SurrenderThrowIn`, or in a `Defense` whose pairs are all covered. Each state is reduced to a position key (seat, phase, attacker/defender, table pairs and, for surrender, the hand) that arms one timer in an effect, so an unrelated socket push never restarts the grace and a fired key never fires twice. ### 3.3 Interaction & Web Audio Subsystems
- **Magnetic Drag-Snap & Double-Click:** Pointer drag handlers compute Euclidean distance to valid drop zones, snapping a preview highlight when within `48px`. Double-clicking a hand card evaluates all legal actions for that card and dispatches immediately if and only if exactly one target/action is legal.
- **`SoundEngine.ts`:** Synthesizes procedural sound effects via the browser Web Audio API (card slap thuds at distinct pitches for attack/cover/redirect/surrender, player-specific page-turn brushes on talon draw, 5-second clock warning ticks, and a Lichess-style two-note game-over chime). Five packs (`SOUND_PACKS`) each voice every `SoundEvent`; `playSampleSound(pack?, volume?)` previews a random effect from `SAMPLE_EVENTS`, optionally through a one-off preview gain bus at the supplied volume, without mutating the persisted pack or volume.

### 3.4 Card Rendering (`components/Card.tsx`)
- `Card.tsx` draws every face in an inline SVG `viewBox="0 0 70 100"`. Number ranks map to fixed pip tables centred on `(35, 50)`; aces get one large ornate pip pinned to `(35, 50)`; `J`/`Q`/`K` render a center letter at `(35, 50)`. Both the ace pip and the centre letters carry `dominant-baseline="central"`.
- **Face pips (`class="card-pip face-pip"`):** `judge`-style corner tables place pips at the ends of the letter — `jack` = 3 (`top-left`, `top-right`, `bottom-left`), `queen` = 1 (`bottom-right`), `king` = 4 (all corners). Each pip carries `data-corner`, `data-rotation`, and `transform="rotate(angle x y)"`.
- **Reserved corner index (`CARD_INDEX`, T-90 ITEM-3a):** the corner rank and its suit pip share a single `text-anchor="middle"` column at `x = 11.5` (top-left) and `x = 58.5` (bottom-right, mirrored across the card centre), so the pip is exactly centred beneath the rank on every rank — `2`–`9`, the two-digit `10`, `J`, `Q`, `K` and `A`. The rank is 15pt in a band ending at `y = 21` (`y = 96` at the bottom); the corner suit is 12pt (up from 10) at `y = 34` (`y = 82` at the bottom) and carries `data-testid="card-suit-top"` / `card-suit-bottom`.
- **Numbered-card face pips (`PIP_LAYOUTS`, T-90-1 ITEM-3a):** `PIP_COLUMNS` (`22.5` / `35` / `47.5`), `PIP_ROWS` (`32` / `44` / `50` / `56` / `68`) and the exported `PIP_LAYOUT_BOUNDS` (`22.5`–`47.5` × `32`–`68`) place the grid strictly centred on the `70x100` viewBox. `left + right = 70` and `top + bottom = 100`, so every rank's pip bounding box has equal left/right (`22.5` from either edge) and top/bottom (`32` from either edge) margins, the centre column lands on `x = 35` and the centre row on `y = 50`; the `7`/`8`/`10` centre pips mirror on `y = 44` / `56` and the `6`/`7`/`8` middle row mirrors on the side columns. Every pip is `PIP_FONT_SIZE = 13` (~10.4 units of ink wide), still disjoint from the corner index band, the enlarged corner suit, the top-right trump badge at `(61, 10)` with `r = 6` and every neighbouring pip (including the 2×4 + 2-centre `10` layout). `ACE_PIP = { x: 35, y: 50, fontSize: 40 }` pins the ornate centrepiece to the exact card centre with `text-anchor="middle"` and `dominant-baseline="central"` (equal `35`/`35` and `50`/`50` margins), and the `J`/`Q`/`K` centre letters plus their 11pt decoration pips mirror around `(35, 50)`. `Card.test.tsx` measures glyph ink (`GLYPH_METRICS`) to assert the equal margins and the zero-overlap geometry.
- **Theme-dependent card front:** `cardFrontPalette(theme)` returns `LIGHT_CARD_FRONT_PALETTE` (`face: #ffffff`, border `#bababa`) or `DARK_CARD_FRONT_PALETTE` (`face: #cbd5e1`, border `#94a3b8`). `resolveCardFrontTheme(theme, prefersDark?, root?)` honours an explicit `light`/`dark`, otherwise reads the `data-theme` written to `<html>` by `settings.ts`, then falls back to `prefers-color-scheme`; `useCardFrontTheme` re-renders `Device theme` cards when the OS scheme changes. The resolved palette fills both the SVG face `<rect>` and `data-card-face`, and `data-card-theme="light" | "dark"` is exposed on the card wrapper and the SVG for CSS and tests.
- **Card typography (T-90):** two font stacks are exported from `Card.tsx`. `CARD_CORNER_FONT_FAMILY` (`Inter, system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`) paints the small corner rank indices on every rank — `<text class="card-rank-index" data-index="top-rank" | "bottom-rank" data-testid="card-rank-top" | "card-rank-bottom" data-font-style="sans-serif" font-weight="700">` — and `CARD_SERIF_FONT_FAMILY` (`'Cinzel', 'Playfair Display', Georgia, 'Times New Roman', 'Palatino Linotype', 'Book Antiqua', serif`) is reserved for the large centre court letter — `<text class="card-face-letter" data-pip="face" data-testid="card-face-letter" data-font-style="serif" font-weight="700">` on `J`/`Q`/`K` only. Because a CSS declaration outranks the SVG `font-family` presentation attribute, `table.css` mirrors both stacks: the shared `.playing-card text` rule keeps the serif stack for the pips, the more specific `.playing-card .card-rank-index` rule repaints the corners sans-serif, and `.playing-card .card-face-letter` pins the ornate serif stack; `Card.test.tsx` asserts all three rules stay in sync with the exported constants. The typeface pass itself left every `CARD_INDEX`, `PIP_LAYOUTS`, `ACE_PIP` and `TRUMP_BADGE` coordinate untouched; T-90-1 (ITEM-3a/ITEM-3b) then re-centred the pip grid (`22.5` / `35` / `47.5` × `32`–`68`) and moved the ace pip to `(35, 50)`, and the zero-overlap geometry tests still pass.
- **Roundness-driven card corners (ITEM-NEW-1b):** `svgCornerRadius(roundness)` in `CardBack.tsx` maps the global `0`–`16 px` Roundness setting onto the `70x100` viewBox (`0` → `0`, default `8` → `6`, `16` → `12`). `Card.tsx` reads `useSettings()` and passes the result as `rx`/`ry` to its face frame `<rect>`; `CardBack.tsx` uses it for the outer frame `<rect>` and `Math.max(0, svgCornerRadius - 1.5)` (→ `0` / `4.5` / `10.5`) for both inner decorative `<rect>`s (the pattern fill and the colourful motif overlay). Both `.playing-card`/`.playing-card-back` SVGs and the `.card-slot` wrapper expose `data-roundness={String(settings.roundness)}` and bind `border-radius` to `var(--app-roundness, 8px)`; `styles/table.css` binds the `[data-zone='table-arena']` border and its felt `::before` layer to the same variable, so the slider reshapes cards and the game table together.
- **Outward rotation:** `facePipAngle(suit, corner)` returns `-45` / `45` / `135` / `-135` for hearts & clubs (distinguishing top half faces out) and the 180-degree opposite set (`135` / `-135` / `-45` / `45`) for spades & diamonds (bottom half faces out).
- **Trump marker:** the gold badge is a `circle` at `(61, 10)` with `r=6` and an 8pt suit glyph (≈13.7px on an 80px card), so it sits inside the rounded top-right corner and never intersects the rank pips, the ornate ace pip or the face letter.

### 3.5 REST & WebSocket Client (`api/`)
- **`client.ts`:**
  - `createGame(playerCount, playerNames, allowRedirect, chaosMode, playerTypes?)` → `POST /api/game/create`; `playerTypes` is `readonly PlayerType[]` (`'human' | 'randomBot' | 'basicBot'` per seat) and defaults to all `'human'`.
  - `checkServerHealth()` → `GET /api/health`, resolving `true` for a 2xx response and `false` for any error, so the lobby can poll backend readiness.
  - `getGameView()` and `sendAction()` validate every payload with `parsePlayerGameView`.
  - `getGameReplay(gameId)` → `GET /api/games/:gameId/replay`, validated by `parseGameReplay` (`ReplayFrame`, `RecordedMove`, `GameReplay` in `types.ts`); each frame's `views` go through `parsePlayerGameView`, so replay mode consumes the same trusted projection as the live table.
- **`websocket.ts` (`GameWebSocket`):**
  - Validates each frame through `parsePlayerGameView` and ignores control/malformed frames (`{"type":"pong"}`, bare pings, empty payloads) without touching UI state.
  - Sends `{"type":"ping"}` every `20_000ms` while `OPEN` as an application-level heartbeat (the server also pushes a WebSocket `Ping` every 20 s and now allows a 10-minute idle timeout instead of Ember's 60-second default); the timer is cleared on close and `disconnect()`.
  - `sendPresence(isPresent)` emits `{"type":"presence", isPresent}`, queues the latest value until `onopen`, and re-sends it after an automatic reconnect.
  - Reconnects with 1s/2s/4s exponential backoff, at most three retries.
- **`types.ts` presence fields:** `PlayerType = 'human' | 'randomBot' | 'basicBot'`; `PublicPlayerSummary.isPresent` and `PlayerGameView.presentPlayers` are optional, validated by the parser when present.

### 3.6 Hand Layout, Felt Filters & Presence
- **Hand geometry (`GameTable.tsx`):** `handLayout(count, availableWidth, cursorFraction, cardWidth)` returns `{ overlap, visibleCount, hiddenLeft, hiddenRight }`. Overlap starts at `HAND_MIN_OVERLAP = 8px` and tightens only up to `cardWidth - max(12px, 28% of the card width)`, so the top-left rank/suit index stays readable; past that capacity the surplus stacks at 100% overlap on the ends. `handMargins()` turns the layout into per-slot negative margins, `.hand-slot[data-hidden='true']` drops behind the visible row (`z-index: 0`, no pointer events), and pointer movement across `.hand-cards` moves cards between the hidden left/right stacks. `handOffsets()`/`handMargins()` never wrap: `.hand-cards` is `flex-wrap: nowrap`. Opponent seats use `opponentOverlap()` inside a fixed `208×32` row that reacts only to card count. Widths are measured with a `ResizeObserver` on the hand column, falling back to `HAND_FALLBACK_WIDTH` when layout is unavailable.
- **Felt layer:** the arena carries `data-texture` plus `--table-filter` from `useSettings()`, and `[data-zone='table-arena']::before` paints `--table-felt`/`--table-felt-overlay` across the whole grid while `filter: var(--table-filter)` applies brightness/contrast/hue to the surface only — cards stay untinted and match the header's live previews.
- **Theme-dependent felt (`table.css`):** every `[data-texture='…']` block also declares `--table-felt-light`, `--table-felt-overlay-light` and `--table-felt-border-light` (the pale sage/navy/rose/slate/olive/sand variants). A `:root[data-theme='light'] [data-zone='table-arena']` rule remaps `--table-felt`/`--table-felt-overlay` to those light values and adds a `lightBorder` inset frame on `::before`, so switching the theme repaints the felt with no `GameTable`/`GamePage` change. The same light block pales `.seat-box`, `.battlefield-tinted-box`, `.target-outline`, `.redirect-outline`, `.talon-count`/`.deck-count-badge`, `.trump-badge` and `.sort-select`, darkens their text to `#0f172a`/`#1e293b`, and outlines `.texture-swatch` previews (whose background is inline) with a thin slate inset ring. A later `html[data-theme='light']` block (T-90) remaps every emphasis to the same semantic families: the light keyframes `lightAttackerHandPulse`, `lightDefenderHandPulse` and `lightUncoveredPulse` read `var(--role-attacker-glow)` / `var(--role-defender-glow)`, `.hand-cards.attacker-turn` / `.throw-in-turn` carry `var(--role-attacker-border)`, `.hand-cards.defender-turn` carries `var(--role-defender-border)`, `.card-slot.trump` and `.trump-badge` use `var(--trump-accent)` / `var(--trump-border)`, `.table-pair.turn-pulse .card-slot` and `.table-card-uncovered .card-slot` use the crimson uncovered pulse, `.target-outline` (including `.snap-active`) uses the emerald family while `.redirect-outline` uses violet, the `.action-button.red` / `.green` / `.amber` table buttons glow in their own families, and `.seat-clock.active` / `.hand-clock.active` use `--clock-active-*`. The light `.sort-select` uses `var(--ui-select-border)` with a `var(--ui-select-glow)` resting/hover halo. `[data-theme='light'] .presence-dot.present` keeps its `#15803d` core with a `0 0 8px 2px rgba(21, 128, 61, 0.7)` halo as the presence indicator (a separate concern from the attacker role). `[data-table-theme='light']` mirrors the arena selectors where a table opts into the light emphasis independently of the shell.
- **Trump placement:** `.table-trump-card` uses `transform: translate(8px, -6px) rotate(90deg)` (5px/-4px on small screens), so the horizontal trump tucks under the vertical talon instead of overflowing its left/bottom edges.
- **Presence:** `GamePage` tracks `document.hasFocus()` plus 30-second mouse/keyboard activity (`PRESENCE_IDLE_MS`), reports changes through `GameWebSocket.sendPresence`, and renders `presence-dot` in every `PLAYERS` row from `PlayerGameView.presentPlayers`, `PublicPlayerSummary.isPresent`, or the local activity state for the viewer. Dots are green (`--durak-accent`) when present and grey otherwise.
- **Frozen clocks:** `viewerOnClock` compares `turnPlayerId` with `myId`; the right-sidebar clock renders `00:15` with `data-active="false"` unless the viewer is the timed player, while each seat and hand clock shows its own player's remaining seconds.
### 3.7 Lobby Readiness & Seat Types (`pages/LobbyPage.tsx`, `app.tsx`)
- **App shell:** `App` renders `<HeaderBar />` directly above the routed page with no `<h1 class="app-title">` — the `LIDURAK` brand link already titles every page, so the duplicate heading is gone.
- **Readiness gate:** `LobbyPage` probes `checkServerHealth()` (i.e. `GET /api/health`) on mount and then every `1000 ms` until it succeeds. While the backend is not ready it renders the themed `.server-loading-page` block (`data-testid="server-loading"`, `role="status"`, message `Starting game server, please wait…`) containing the `.lobby-loading-spinner` ring (`data-testid="lobby-loading-spinner"`) — a circular border with a high-contrast accent top/right segment animated by the `lidurak-spin` keyframes (0.85 s linear, infinite) in `app.css` — instead of the form, so no click can reach a proxy `HTTP 500`; the poll unlocks the form on its own once the server answers.
- **Warm-up recovery:** a `createGame(...)` failure that looks like a booting backend — an `HTTP 500` / `502` / `503` / `504` message or a `TypeError` from `fetch` — drops the lobby back into the loading state and re-polls instead of showing an error banner. Any other failure (for example an unsupported player count) still renders `.error-banner`.
- **`initialServerReady?: boolean` prop:** starts the lobby unlocked and skips the probe; tests and caller-known server state use it, the app itself leaves it unset.
- **Seat types:** `playerTypes` state mirrors the seats (`['human', 'human']` initially), stays length-matched when the count changes and preserves earlier choices, and is passed as the fifth `createGame(...)` argument. Every player row renders its name `<input>` plus a `<select data-testid="player-type-<index>" aria-label="Player <n> type">` offering `Human` / `RandomBot` / `BasicBot` in that order (`human` / `randomBot` / `basicBot` values, matching the backend's canonical `GameConfig.playerTypes`); the state is typed `PlayerType[]`.
- **Theming:** every lobby element uses the shared token-driven classes (`lobby-form`, `field`, `name-fields`, `checkbox-field`, `.server-loading-page`, `created-game`, `player-tabs`, `error-banner`), so the Create a Game page follows `html[data-theme='light']` without page-specific colour overrides.
