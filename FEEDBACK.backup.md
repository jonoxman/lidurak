1. Collapse table cards together as they are covered if there is not sufficient space. As cards are played into the game table area, they should always stay collected in one row. If necessary, this will require reducing the gaps between the cards already on the table when a new card is added, or even allow overlap. Implement it as follows: Pairs of cards that are already covering/covered should be moved to the nearest vertical edge of the game table (left or right, depending on the target player), since they cannot be further interacted with directly. Multiple instances of these covering card pairs on the table should be overlapping maximally in such a way that the suit and rank of all cards is still visible, in a similar way to how the hand maximally overlaps. Remaining active as-yet uncovered cards should maintain a small gap between each other and the covered cards by default, but they can be allowed to overlap slightly if necessary to keep all cards on one single row in the game table area. 
2. The '10' rank number on the cards is too small in font size compared to the other numbered cards. Adjust the font size so that the size is consistent between cards. Make sure to adjust the maximum card overlap in the hand and other places to ensure the full rank of the card is always visible. Adjust also the size of the suit indicator on the sides of the cards so that it will make full use of this increased width.
3. Bug: Clicking and dragging a card makes it move with the mouse as it should, but with a horizontal offset that seems to increase the farther right the card appears in the hand. The card should always follow the mouse as it is dragged without any offset.
4. The timer appearing above the active user's hand is being cut off by the adjusted position of the cards when they are shifted due to being selected or being shown to be eligible to be played. Adjust its position so it is never overlapped by another game element, while still being in the same general location.
5. For large hands, never decrease the size of the cards in hand. Instead, the rules for displaying the cards should be as follows: By default, there is a box the cards are constrained to, whose width is the current width of a 6-card hand as it is currently implemented (including overlap). There is also a maximal box, which should be almost the entire width of the play area with a small margin on both sides. Cards in the hand should be displayed with the maximal allowable overlap until their width exceeds that of this maximal box. After this, the overlap of the cards should be increased even beyond the current maximum allowable amount (so the suit and rank of the card need not be fully visible). 
6. Mousing over the hand should have a smooth animation to "part" the cards (that is, reduce the overlap for the cards that the mouse is currently close to, while increasing the overlap for the other cards farther from the position). Ensure that the animation is smooth and aesthetically clean. If there is only one card in the hand, the animation should not play. The card actually being moused over should not change its position due to this animation.
7. Move the surrender and pass buttons onto the lower part of the game table area, instead of in the bottom right corner. They should be positioned in such a way that they never overlap any other gameplay elements. 
8. Instead of using the same vertical adjustment for cards that are playable and cards that have been selected by the user, put it in two tiers: eligible cards to be played should be vertically raised halfway to the current level, and selected cards should be raised fully to the current level.
9. Reduce the number of QA scenarios, removing those that are not needed for the current round of QA testing.
