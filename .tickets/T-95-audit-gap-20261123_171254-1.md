# T-95: Wire `useRoute` History-API Router & Live M2 Multiplayer Room / Projected Table View (`/g/:gameId`)

## Context & Audit Findings
Milestone M2 backend services (`SessionRoutes`, `RoomManager`, `QuickPairingService`, `MultiplayerRoutes`, `QaPresetRoutes`) and the homepage lobby (`LobbyPage.tsx`, `QuickPairingTab`, `LobbyPoolTab`, `CreateInviteTab`, `QaLobbyPresets`) are implemented, **but the `/g/:gameId` route and multiplayer room view are completely unwired in the live frontend**:
1. `frontend/src/router/useRoute.ts` (History-API router for `/` and `/g/:gameId`) is never mounted in `frontend/src/App.tsx`.
2. `frontend/src/pages/LobbyPage.tsx` navigates via `window.location.hash = '#/g/' + encodeURIComponent(gameId)` instead of using `useRoute.ts` History-API navigation (`/g/:gameId`), which also mismatches the backend's `inviteUrl: "/g/${room.gameId}"`.
3. `frontend/src/api/gameSocket.ts` (`createGameSocket` -> `WS /ws/games/:gameId`) and `frontend/src/api/lobbyClient.ts` (`fetchGameView` -> `GET /api/games/:gameId`, `leaveRoom` -> `POST /api/games/:gameId/leave`) are never called in any live frontend page.
4. Clicking Quick Pairing, Lobby Pool Join, Create Invite Link, or the QA Scenario Presets (`Launch 2P invite room (1/2)`, `Launch active projected match`, `Launch spectator zero-leak view`)—or directly opening a shareable `/g/:gameId` invite URL—does not render a live M2 `PlayerGameView` room.

## Requirements

### 1. Wire History-API SPA Routing in `App.tsx` & `LobbyPage.tsx`
- Update `frontend/src/App.tsx` to use `useRoute()` from `frontend/src/router/useRoute.ts`:
  - When the pathname matches `/g/:gameId` (route `game`), render the new M2 `MultiplayerGamePage` (passing `gameId` and a navigation callback back to `/`).
  - Preserve existing M1 local/bot hotseat routing (e.g., whatever hash or route mechanism M1 `LobbyPage` uses for local games created with `playerNames` -> M1 `GamePage.tsx`) so M1 local matches and M1 QA presets continue to work unchanged.
  - Otherwise render `LobbyPage`.
- Update `frontend/src/pages/LobbyPage.tsx`:
  - Replace `window.location.hash = '#/g/' + encodeURIComponent(gameId)` in `openGame(gameId)` with the History-API navigation helper exported by `frontend/src/router/useRoute.ts` (e.g. `navigateToGame(gameId)` / `navigate('/g/...')`), so Quick Pairing, Lobby Pool Join, Create Invite Link, and all room-launching QA Lobby Presets navigate to `/g/:gameId`.
- Verify `frontend/vite.config.ts` proxies `/api` and `/ws` (with `ws: true`) to `http://localhost:8080` and serves the SPA `index.html` cleanly on direct reloads of `/g/:gameId`.

### 2. Implement Live M2 Multiplayer Room & Projected Game View (`frontend/src/pages/MultiplayerGamePage.tsx`)
Create `frontend/src/pages/MultiplayerGamePage.tsx` (and accompanying CSS in `frontend/src/styles/lobby.css` or a dedicated stylesheet following strict zero-overlap CSS Grid/Flexbox rules—**NO `position: absolute` or `position: fixed`** for layout panels, seats, hands, bouts, or sidebars, and **zero table text clutter**).

#### Session & WebSocket Lifecycle (Prevent First-Visit Auth Race)
- On mount for a given `gameId`:
  1. First ensure the visitor's `HttpOnly` guest cookie is established by awaiting `getOrCreateSession()` (and `fetchGameView(gameId)` via `GET /api/games/:gameId`).
  2. Only **after** the session/initial view request resolves (so the `lidurak_session` cookie is set for first-time visitors opening a shared invite URL), open `createGameSocket(gameId, { onView, onActionRejected, onStatusChange })`.
  3. On unmount or `gameId` change, call `socket.dispose()` cleanly.
- If `fetchGameView` returns 404 (room not found), render a clear not-found state with a **"Back to Lobby"** button (`navigateToLobby()`).

#### State A: `WaitingForPlayers` (Shareable Invite Room)
When `view.status` is `WaitingForPlayers`:
- Render room header with `gameId`, player count (`filled / playerCount`), deck size (`36-card` / `52-card`), turn timeout (`Xs`), Redirect `ON`/`OFF`, Public/Private badge, and live WebSocket status badge.
- Render the full shareable invite URL (`${window.location.origin}/g/${view.gameId}`) with a **"Copy Invite Link"** button (`navigator.clipboard.writeText` with visual copied feedback).
- Render all `view.seats` (`RoomSeatView[]`): seat number, occupied player `displayName` or `Open seat`, and live `isConnected` presence indicator.
- If `view.viewerSeat === null` and an open seat exists, render a **"Join Seat"** button (`joinRoom(gameId)`) that updates `view` immediately with the returned `PlayerGameView`.
- If `view.viewerSeat !== null`, render a **"Leave Room"** button (`leaveRoom(gameId)`) that returns the user to `/` (`navigateToLobby()`).
- Render a **"Back to Lobby"** button (`navigateToLobby()`).

#### State B: `InProgress` & `Finished` (Projected Match & Zero-Leak Spectator View)
When `view.status` is `InProgress` or `Finished`:
- Render the Lichess 3-column desktop shell (`[data-zone="sidebar-left"]`, `[data-zone="table-arena"]`, `[data-zone="sidebar-right"]`) using CSS Grid/Flexbox (`#161512`, `#262421`, `#1e2923`, `#629924`, `#c33`):
  - **`sidebar-left`**: Match info (gameId, Redirect ON/OFF, live connection status), **"Spectator Mode (Read-Only)"** badge when `view.viewerSeat === null`, opponent/player roster with `isConnected` dots and `cardCount`, and **"Back to Lobby"** button.
  - **`table-arena` (3x3 CSS Grid felt table, zero text clutter)**:
    - Row 1: Opponent seats (`PublicPlayerSummary`: name, `cardCount`, `isConnected` status, `hasPassed`, `finishRank`, attacker/defender indicator — never showing opponent card faces).
    - Row 2: Active bout `table` pairs (`TablePair[]`), interactive defense target selection when defending, and redirect target when applicable.
    - Row 3: Col 1 (`data-zone="table-deck"`): Talon `deckCount`, `trumpCard` / `trumpSuit`; Col 2 (`data-zone="player-hand"`): Strictly `view.hand` (`Card[]`) when `view.viewerSeat !== null` (empty / hidden controls when `view.viewerSeat === null` in Spectator Mode); Col 3: Contextual `Pass` / `Take` (Surrender) buttons wired to `socket.sendAction({ type: 'pass' })` / `socket.sendAction({ type: 'take' })` ONLY when seated (`view.viewerSeat !== null`).
  - **`sidebar-right`**: Digital `00:XX` turn clock driven by `view.turnDeadlineEpochMs` (or `view.config.turnTimeoutSeconds`), and winner / Durak standings when `view.status === 'Finished'`.
- Wire player card actions strictly through `socket.sendAction(...)` (`playAttack`, `playDefend`, `playRedirect`, `pass`, `take`) using the exact `WsClientMessage` wire schema in `frontend/src/types/multiplayer.ts`.
- Ensure zero opponent private cards exist or are rendered in Spectator Mode (`viewerSeat === null`, `hand: []`).

### 3. Verify All M2 QA Scenario Presets End-to-End
Confirm all 4 buttons in `QaLobbyPresets.tsx` work end-to-end:

- `qa-spectator-match`: navigates to `/g/:gameId` and renders the live `InProgress` match in Spectator Mode (`viewerSeat: null`, `hand: []`, read-only).
