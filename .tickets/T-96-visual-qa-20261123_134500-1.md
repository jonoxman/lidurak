# Fix Profile Menu Trigger Identification, Slider-Drag Dismissal Guard, and Hand/Throw-In SVG Conformity

## Summary of Visual & Browser QA Failures
1. **11 Playwright verification failures on Items 2 & 3 (`pageErrors` in `.reviews/visual_qa_telemetry.json`):**
   - In `frontend/src/components/HeaderBar.tsx`, `.profile-button` (`aria-label="Account menu"`, lines 708–718) has no `data-testid` (e.g., `data-testid="profile-button"` / `data-testid="profile-menu-trigger"`), and `.profile-dropdown` (line 734) has no `data-testid="profile-dropdown"`.
   - Meanwhile, all four top-level navigation menu triggers (`PLAY`, `PUZZLES`, `LEARN`, `WATCH`, lines 683–692) also carry `aria-haspopup="true"` and their `<ul class="header-menu-dropdown">` lists (line 693) also carry `role="menu"`.
   - As seen in `step_2_item_3_lobby_profile_open.png`, `step_2_item_3_lobby_theme_submenu_open.png`, `step_3_item_2_roundness_min.png`, `step_3_item_2_roundness_max.png`, and `step_2_item_3_game_sound_submenu_open.png`, automated selectors matching `header button[aria-haspopup]` and `header [role="menu"]` interacted with the `PLAY` navigation menu instead of the profile menu (`Guest`), preventing `[data-testid="submenu-theme"]`, `[data-testid="submenu-sound"]`, and the Roundness slider checks from executing.
2. **Slider-drag outside-release prematurely closes the profile dropdown (`frontend/src/components/HeaderBar.tsx`):**
   - The outside-press dismissal `useEffect` (lines 588–615) registers capture-phase listeners on `['pointerdown', 'mousedown', 'click']`. When a user presses down on a range slider inside `.profile-dropdown` (such as `Roundness`, `Glow`, or `Volume`), drags past the dropdown boundary, and releases outside `.header-profile`, the browser dispatches a synthetic `click` event on the common ancestor outside `profileMenuRef.current`, closing the menu mid-adjustment.
3. **Hand highlight SVG stroke join at `Roundness = 0` (`frontend/src/components/GameTable.tsx`, `frontend/src/styles/table.css`):**
   - `<path class="hand-highlight-path">` (line 3433–3439) and `.hand-highlight-path` (`table.css` lines 1327–1337) hardcode `stroke-linejoin: round` and `stroke-linecap: round`. When `settings.roundness === 0` (`contourCornerRadius === 0`), `buildHandContourPath` produces sharp `M ... L ... Z` vertices, but `stroke-linejoin: round` still slightly rounds the `2.5px` stroke corner instead of rendering a sharp mitered corner.
4. **`HIGHLIGHT_SIZE_MISMATCH` on `throw-in-outline` (`frontend/src/components/GameTable.tsx`, `frontend/src/styles/table.css`):**
   - `div[data-testid="throw-in-outline"].target-outline.throw-in-outline` reports `Wrapper (100x140) does not conform tightly to child (40x57)` on every game-page capture because `.throw-in-icon` (`GameTable.tsx` line 2771, `table.css` line 2802) uses `width: 42%; height: 42%;` with `viewBox="0 0 40 40"` instead of filling the `100x140` card slot (`width: 100%; height: 100%;`) with centered artwork like sibling `.redirect-outline` / `.redirect-arrows`.

## Required Changes

### 1. `frontend/src/components/HeaderBar.tsx`
- Add `data-testid="profile-button"` to `<button type="button" class="profile-button" ...>` while **preserving** `aria-label="Account menu"`, `aria-haspopup="true"`, and `aria-expanded={profileOpen}` (required by `HeaderBar.test.tsx`).
- Add `data-testid="profile-dropdown"` to `<div class="profile-dropdown" role="menu" aria-label="Profile menu">`.
- Keep `aria-haspopup="true"` on the `NAV_MENUS` `.header-menu-trigger` buttons (required by `HeaderBar.test.tsx`).
- In the `useEffect` for `profileOpen` (lines 588–615), track whether `pointerdown` / `mousedown` originated inside `profileMenuRef.current` (e.g., via a `pressedInsideRef` boolean ref):
  - On `pointerdown` / `mousedown`: if `container.contains(target)`, set `pressedInsideRef.current = true` and return; otherwise set `pressedInsideRef.current = false` and call `closeProfileMenu()`.
  - On `click`: if `container.contains(target)`, clear `pressedInsideRef.current = false` and return; if `pressedInsideRef.current` is `true` (a drag started inside, such as dragging the Roundness/Glow/Volume slider, and released outside), clear `pressedInsideRef.current = false` and return without closing; otherwise call `closeProfileMenu()`. (Standalone `click` events outside the menu with no prior inside press—such as `fireEvent.click(document.body)` in unit tests—must still close immediately.)

### 2. `frontend/src/components/GameTable.tsx` & `frontend/src/styles/table.css`
- **Sharp corners at `Roundness = 0`:**
  - Keep `.hand-highlight-path { stroke-linejoin: round; stroke-linecap: round; }` in `table.css` and keep `stroke-linejoin="round"` / `stroke-linecap="round"` when `contourCornerRadius > 0` (so `GameTable.test.tsx` default-roundness assertions at lines 5246–5272 continue to pass).
  - When `contourCornerRadius <= 0` (`settings.roundness === 0`), set `stroke-linejoin="miter"` and `stroke-linecap="square"` on `<path class="hand-highlight-path">` and add `.hand-highlight-contour[data-contour-radius='0'] .hand-highlight-path { stroke-linejoin: miter; stroke-linecap: square; }` in `table.css`.
- **`throw-in-outline` SVG sizing:**
  - In `GameTable.tsx` (`throwInOutline`, lines 2771–2773), update `<svg class="throw-in-icon" ...>` to `viewBox="0 0 100 140"` with the centered `+` path (`d="M50 53 L50 87 M33 70 L67 70"`).
  - In `table.css` (lines 2802–2810), update `.throw-in-icon` from `width: 42%; height: 42%;` to `display: block; width: 100%; height: 100%;` (matching `.redirect-arrows` at lines 602–606), keeping the same `stroke`, `stroke-width`, `stroke-linecap`, and `opacity`.
