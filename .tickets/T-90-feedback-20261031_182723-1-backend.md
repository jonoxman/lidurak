# Ticket T-90-feedback-20261031_182723-1: Backend Warnings, SLF4J Logging, Short Game IDs, Turn Clock & Auto-Play, and Defenseless Auto-Surrender Engine

## Subsystem
Backend (Scala 3 / Cats Effect / http4s / Ember)

## Wave
WAVE:1 (Runs concurrently with Wave 1 Frontend tickets)

## Description & User Requirements
Address backend compiler warnings, missing SLF4J provider, game ID length limit, turn timeout auto-play, and defenseless auto-surrender logic:
1. **Fix Compiler Warnings & SLF4J Provider (Feedback Item 0)**:
   - Eliminate the pattern match warning at `backend/src/main/scala/durak/engine/GameEngine.scala:78:11` (`case other =>` unreachable except for null). Genuinely fix the match logic (e.g. exhaustiveness or precise case matching) without suppressing warnings.
   - Resolve deprecation warnings reported across Scala sources when compiled with `-deprecation`.
   - Fix `SLF4J: Failed to load class "org.slf4j.impl.StaticLoggerBinder"` / `Defaulting to no-operation (NOP) logger implementation` by adding a genuine logging provider to `backend/build.sbt` (e.g., `org.slf4j % slf4j-simple % "2.0.12"` or `ch.qos.logback % logback-classic % "1.5.3"`). Verify log messages appear cleanly on server startup.
2. **Short Game IDs (Feedback Item 16)**:
   - Reduce the generated game ID length in `backend/src/main/scala/durak/server/GameManager.scala` to at most 8 characters containing only alphanumeric characters (`[a-zA-Z0-9]`, e.g. 6 to 8 chars).
   - Ensure routes, WebSocket handlers, and codecs correctly support short 8-char game IDs without regression.
3. **Turn Activity Clock, Auto-Play on Expiry, & Resets (Feedback Item 14)**:
   - Ensure the server tracks active turn deadlines and remaining seconds for whichever player is being waited on to act.
   - When the clock expires (e.g., 15 seconds), the engine must automatically execute a valid random legal move for the timed-out player (choosing randomly among available legal actions: pass, throw-in, defend with a legal card, attack with a card, redirect, or surrender).
   - The player's clock must reset whenever any player takes a valid action.
   - Expose the active clock deadline and per-player turn status in `PlayerGameView` and WebSocket broadcasts so clients can display remaining time above each player's box.
4. **Defenseless Auto-Surrender Engine Support (Feedback Item 18)**:
   - When a player is under attack and has zero legal defensive moves (no card can legally beat or trump any uncovered attack, and no redirect is possible), flag or record this defenseless state in the engine/view. Provide server support or a 3-second grace transition for auto-surrender so client or server can cleanly execute the surrender action if the defender does not surrender beforehand.
