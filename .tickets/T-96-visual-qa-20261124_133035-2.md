# T-96-visual-qa-20261124_133035-2: Hook M1 Gameplay Interface into Multiplayer Rooms, Remove Placeholder UI, and Keep Small-Hand Hover Width Constant

## Visual & Telemetry Findings
Inspection of `.reviews/visual_qa_telemetry.json` and `.reviews/screenshots/` against `<implemented_feedback>` reveals two unimplemented/failing gameplay requirements:

1. **New #3 — Lightweight Placeholder Interface Still Rendered in Multiplayer (`step_14_item_3_multiplayer_m1_table.png`, `step_15_item_3_multiplayer_card_played.png`, `step_16_item_3_multiplayer_turn_resolved.png`, `step_17_item_3_multiplayer_spectator_m1_table.png` vs `step_18_item_3_local_m1_table_comparison.png`):**
   - `frontend/src/pages/MultiplayerGamePage.tsx` still renders `ProjectedTable` (`.mp-shell`, `.mp-sidebar`, `.mp-arena`, `.mp-seat`, `.mp-bouts-row`, `.mp-deck`, `.mp-hand`, `.mp-actions` with `Play` / `Cover` / `Redirect` / `Pass` / `Take` buttons and small `64x90` / `72x100` cards) instead of the Milestone 1 gameplay interface (`GameTable`, `TableDeck`, `ActionBar`, `SortBar`, `.game-shell` 3-column layout, split `Game`/`Turn` clock, `How to Play` panel, theme/felt texture/card-back integration).
   - Both `ProjectedTable` in `MultiplayerGamePage.tsx` and the `.mp-*` placeholder table styles in `frontend/src/styles/lobby.css` remain in the project instead of being removed completely.

2. **New #4 — Small-Hand Overall Width Expands on Mouseover (`step_19_item_4_6card_resting.png` vs `step_21_item_4_6card_hover_middle.png`):**
   - In `step_21_item_4_6card_hover_middle.png`, hovering the middle card (`10♣`, index 2) of a 6-card hand pushes the rightmost card (`Q♣`, index 5) noticeably rightward past its resting position in `step_19_item_4_6card_resting.png`, widening the overall hand and its SVG highlight contour.
   - Root cause in `frontend/src/utils/handLayout.ts` (`computeLocalizedPartingDeltas`, lines 646–675): when `hovered + window + 1 >= count` (`hasWall === false`), `span` is computed against `rightBound = Math.max(pivot, boxWidth - width)` (the `maximalBoxWidth` of ~652px) instead of the resting hand's own rightmost card `basePositions[count - 1]` (320px for a 6-card hand). Because `rightBound` allows expansion up to `maximalBoxWidth`, cards to the right of the hovered card push outward beyond the resting right edge, increasing the hand's overall width.

## Required Fixes
1. **Wire Milestone 1 Gameplay Interface into `MultiplayerGamePage.tsx` and Remove Placeholder UI:**
   - Replace `ProjectedTable` in `frontend/src/pages/MultiplayerGamePage.tsx` with the Milestone 1 gameplay shell (`GamePage.tsx` layout structure: `.game-page` -> `.game-header`, `.game-shell` with `[data-zone="sidebar-left"]`, `.table-column` containing `GameTable` + `[data-zone="hand-sort-box"]` `SortBar`, and `[data-zone="sidebar-right"]` containing `.clock-split-panel`, `TableDeck`, and endgame results).
   - Map `PlayerGameView` (`src/types/multiplayer.ts`) and WebSocket actions (`playAttack`, `throwInCards`, `coverCard`, `redirectAttack`, `passTurn`, `declareSurrender` via `GameSocket`) onto `GameTable` (`onCardClick`, `onCardDoubleClick`, `onTableCardClick`, `onAttackDrop`, `onCoverDrop`, `onThrowInDrop`, `onRedirectDrop`, `onReorderHand`) and `ActionBar` (`Pass` / `Surrender`), including:
     - Opponent mapping (`PublicPlayerSummary` -> `OpponentSummary`) relative to `viewerSeat` (and spectator fallback when `viewerSeat === null`, rendering `GameTable` in read-only/spectator mode with an empty hand and no action controls).
     - `SortBar` hand sorting (`Rank`, `Suit`, `Pairs`, `Custom`) and sound effects via `SoundEngine`.
     - Turn clock (`turnDeadlineEpochMs` + `config.turnTimeoutSeconds`), attacker/defender role glows, target outlines, and redirect outline.
     - Endgame winner / Durak result banner in the right sidebar / table shell.
   - **Completely remove** `ProjectedTable`, `handDensity`, `mp-shell` / `mp-arena` / `mp-seat` / `mp-bouts-row` / `mp-hand` / `mp-actions` / `mp-deck` placeholder components and CSS rules from `frontend/src/pages/MultiplayerGamePage.tsx` and `frontend/src/styles/lobby.css`.

2. **Keep Small-Hand Overall Width Constant During Mouseover (`frontend/src/utils/handLayout.ts`):**
   - In `computeLocalizedPartingDeltas` (and `computePartedCardLayout` / `GameTable.tsx` if needed), when a hand's resting extent (`basePositions[count - 1] - basePositions[0] + cardWidth`) is smaller than `maximalBoxWidth`, cap the parting bounds so the leftmost card never moves left of `basePositions[0]` and the rightmost card never moves right of `basePositions[count - 1]` (keeping `[min(x), max(x) + cardWidth]` strictly equal to the resting hand width at all times).
   - Specifically, when `hasWall` is `false` (hovering near the right end of a hand), clamp `rightBound` to `basePositions[count - 1]` rather than `maximalBoxWidth - width`, and if opening a gap around the hovered card requires space inside a constant-width hand, spread apart the gap around the hovered card while pushing/compressing neighboring cards together within `[basePositions[0], basePositions[count - 1]]` without increasing the overall width of the hand.
   - Verify across 1-card, 2..6-card (leftmost, middle, rightmost hover), 14-card, and 30-card hands in `GameTable.tsx` that `handContour.width` and `(max(renderedX) + cardWidth) - min(renderedX)` never exceed the resting hand's rendered width during hover.
