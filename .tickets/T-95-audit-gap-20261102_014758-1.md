# Ticket T-95: Complete Game-Over Lobby Button, Split Clock Element, Interactive Replay Navigation, and POV Player Names

## Context & Audit Findings
During the pre-release audit of `main`, four requirements from the human feedback were found to be partially implemented in `GamePage.tsx` and `PlayerGameView`:

1. **Item 9 (Game-Over Banner Lobby Button):** `[data-testid="game-over-banner"]` appears when the game is over and declares the winner/draw and Durak, but does **not** include a button inside the banner to return to the lobby.
2. **Item 10 (Combined Split Clock Element):** The overall game timer (`[data-testid="game-clock"]`) and the 15-second turn timer (`[data-testid="turn-clock"]`) were placed in two separate `<section class="panel">` elements instead of inside the **same** clock element split into two halves vertically. Also, `[data-testid="game-clock"]` sets `data-active="true"` even when `gameStartedAtMs == null` (before the first move).
3. **Item 12 (Interactive Game Review Mode & Move Navigation):** While `getGameReplay(gameId)` is implemented in `frontend/src/api/client.ts` and `/api/games/:gameId/replay` is served by the backend, `GamePage.tsx` never calls `getGameReplay(gameId)` when a game finishes or when visiting a finished game's URL. Furthermore, there are no left and right navigation buttons in the bottom-left of the page (under the "How to Play" element in `[data-zone="sidebar-left"]`) to step through `replay.frames` one move at a time and display each move's board state and frozen game clock time (`elapsedMs`).
4. **Item 13 (POV Menu with Real Player Names):** The left-sidebar player switcher still says `"Hotseat"` / `"You"`, and the header `[data-testid="pov-menu"]` falls back to the active user's raw seat ID (`p0`) because `PlayerGameView` does not expose `myName`.

## Requirements to Implement

### 1. Include `myName` in `PlayerGameView` & Display Real Names in the `POV` Menu (Item 13)
- **Backend (`backend/src/main/scala/durak/engine/PlayerGameView.scala` & `JsonCodecs.scala`):**
  - Add `myName: String = ""` to `PlayerGameView` and populate `myName = viewer.name` in `PlayerGameView.forViewer`.
  - Encode `"myName" -> view.myName.asJson` in `Encoder[PlayerGameView]`, and decode `"myName"` in `Decoder[PlayerGameView]` using `cursor.downField("myName").as[Option[String]].map(_.getOrElse(""))` so existing JSON fixtures without `myName` still decode cleanly.
- **Frontend (`frontend/src/types.ts` & `frontend/src/pages/GamePage.tsx`):**
  - Add optional `myName?: string` to `PlayerGameView` in `frontend/src/types.ts` and parse it in `parsePlayerGameView` (if `raw.myName` is a non-empty string, include it).
  - In `GamePage.tsx`, maintain a `knownNamesRef` (`Record<string, string>`) updated whenever `view` or `replay` arrives: record `view.myId -> view.myName` (when `view.myName` is non-empty) and each `opponent.id -> opponent.name` (plus any names across `replay.frames`).
  - Resolve any player's label via: `opponent.name` -> `view.myId === id && view.myName ? view.myName : undefined` -> `knownNamesRef.current[id]` -> `id` (fallback for unit tests that mock `view` without `myName`).
  - Rename the left-sidebar `"Hotseat"` section (`[data-zone="sidebar-left"]`) heading and `aria-label` to **`POV`**, and display every player button and `[data-testid="pov-menu"]` option by their resolved player name—**never** `"You"`.

### 2. Return-to-Lobby Button Inside the Game-Over Banner (Item 9)
- In `frontend/src/pages/GamePage.tsx`, inside `[data-testid="game-over-banner"]`, render a button (`data-testid="banner-lobby-button"`, text e.g. `Return to lobby` or `Back to lobby`) that calls the same return-to-lobby handler as the header button (`onLeaveGame ? onLeaveGame() : window.location.assign('/')`).

### 3. Single Clock Element Split Vertically into Two Halves (Item 10)
- In `frontend/src/pages/GamePage.tsx` (`[data-zone="sidebar-right"]`), combine the Game timer and Turn timer into a **single** `<section class="panel clock-split-panel" data-testid="clock-panel" aria-label="Game and turn clocks">` split vertically into two halves:
  - Top half (`.clock-half.game-clock-half`): heading `Game` and `<span class="game-clock" data-testid="game-clock" data-active={...}>{gameClock}</span>`.
  - A horizontal divider (`border-bottom` / `border-top` between the two vertical halves).
  - Bottom half (`.clock-half.turn-clock-half`): heading `Turn` and `<span class={clockClasses.join(' ')} data-testid="turn-clock" data-active={...}>{formatClock(seconds)}</span>`.
- Set `data-active` on `[data-testid="game-clock"]` to `'true'` **only** when `!reviewMode && gameStartedAtMs != null && gameEndedAtMs == null` (so it is `'false'` before the first move, after game over, and during replay review).
- Style `.clock-split-panel` and `.clock-half` in `frontend/src/app.css` using CSS Grid / Flexbox so the single panel element is cleanly divided into two equal vertical halves without overlapping.

### 4. Interactive Game Review Mode & Move Navigation in Bottom-Left (Item 12)
- In `frontend/src/pages/GamePage.tsx`:
  - When the loaded game is in `GameOver` phase (`isGameOverPhase(view.boutPhase)`), automatically call `getGameReplay(gameId)` from `../api/client`.
  - Store the loaded `replay: GameReplay | null` and `replayFrameIdx: number` in state. When `replay` loads with `frames.length > 0`, initialize `replayFrameIdx` to `replay.frames.length - 1` (the final move of the game). If `getGameReplay` fails (e.g., in tests that do not mock `getGameReplay` or return a rejection), fall back gracefully to displaying the live `view` in review mode without crashing.
  - When `reviewMode` is active and `replay` has frames, derive the active `displayedView` from `replay.frames[replayFrameIdx]?.views[playerId] ?? replay.frames[replayFrameIdx]?.views[Object.keys(replay.frames[replayFrameIdx].views)[0]] ?? view`.
  - Use `displayedView` to render `GameTable`, `TableDeck`, the `PLAYERS` list, and `[data-testid="game-clock"]`. Because `GameReplay.frozenViews` sets `gameStartedAtMs = 0` and `gameEndedAtMs = frame.elapsedMs` (and `frame.elapsedMs` is also on the `ReplayFrame`), the game clock in `[data-testid="game-clock"]` will remain frozen (`data-active="false"`) at the exact `mm:ss` timestamp when that move was made (`00:00` on frame 0 / move 1, and `formatGameClock(0, activeFrame.elapsedMs, 0)` on frame `k`).
  - In `[data-zone="sidebar-left"]`, at the bottom of the left sidebar (under the "How to Play" element), when `reviewMode` is true, render a review navigation control panel (`data-testid="review-nav"`) containing:
    - Left navigation button (`data-testid="review-prev-button"`, `aria-label="Previous move"`): decrements `replayFrameIdx` by 1 (disabled when at frame `0` or when no replay frames are loaded).
    - Move counter indicator (`data-testid="review-move-indicator"`, e.g. `Move X / Y`).
    - Right navigation button (`data-testid="review-next-button"`, `aria-label="Next move"`): increments `replayFrameIdx` by 1 (disabled when at the last frame `frames.length - 1` or when no replay frames are loaded).
  - Ensure `SortBar` (hand sorting) and the `POV` switcher continue to work seamlessly while stepping through replay frames.

### 5. Documentation Synchronization

  - The interactive replay review mode with bottom-left move navigation buttons under "How to Play".
  - `myName` in `PlayerGameView` and real player names in the `POV` menu.
