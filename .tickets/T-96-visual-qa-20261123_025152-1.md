# T-96-visual-qa-20261123_025152-1: Fix Hover-Parting `data-part-direction` Attributes and Prevent Premature Mount-Time Parting

## Summary of Visual QA Findings
Real Chromium telemetry at `1280x800` and inspection of `.reviews/screenshots/step_2_item_6_30_card_initial.png` and `.reviews/screenshots/step_2_item_6_hover_index_15.png` identified two objective frontend bugs in hand hover-parting:

1. **Missing `data-part-direction` attribute during hover-parting and on resting / 1-card hands (`frontend/src/components/GameTable.tsx`):**
   - In `<browser_visual_telemetry>`, Item #6 Step 4 (`30-Card Compress & Part`) and Step 8 (`1-Card Hand (No Part)`) failed because `partDirection` was `""` (attribute omitted) instead of `"none"` (`Item #6 Step 8: expected 1-card index 0 delta=0 direction=none, got {"index":0,"partDeltaX":0,"partDirection":"",...}`).
   - Root cause: in `frontend/src/components/GameTable.tsx` (lines 3412–3419), `partDirection` is unconditionally set to `undefined` whenever `dragCard === null`:
     ```tsx
     const partDirection: 'left' | 'right' | 'none' | undefined =
       dragCard === null || index === draggedIndex
         ? undefined
         : reorderIndex === null
           ? 'none'
           : effectiveIndex < reorderIndex
             ? 'left'
             : 'right';
     ```
     As a result, `HandCardSlot` (`data-part-direction={partDirection}` at line 254) omits `data-part-direction` during hover parting and on single-card/resting hands.
   - Additionally, `frontend/src/styles/table.css` (lines 2712–2714) has a stale rule:
     ```css
     .hand-card-wrapper[data-part-direction='none'] {
       transform: none;
     }
     ```
     which conflicts conceptually with the comment above it (lines 2707–2711) stating `data-part-direction` must be a testable hint only.

2. **Premature hover-parting on page load/navigation via `onPointerEnter` (`frontend/src/components/GameTable.tsx`):**
   - In `.reviews/screenshots/step_2_item_6_30_card_initial.png`, the 30-card hand is already parted around index `18` (`K♣`) before any mouse movement in the hand, shifting resting `data-card-x` values (`19 -> 384.48`, `20 -> 399.78`, `21 -> 410.1` instead of resting `361.66`, `380.70`, `399.73`).
   - Root cause: clicking the `30-Card Compress & Part` button in the lobby (`step_1_lobby_initial.png`) leaves the stationary pointer at viewport coordinates that overlap `[data-zone="player-hand"]` on the game page. Because `[data-zone="player-hand"]` binds `onPointerEnter={handleHandPointerMove}` (line 3274) and spans the `76px` `--hand-timer-clearance` top padding above `.hand-cards`, Chromium fires `pointerenter` on mount/navigation without pointer motion, immediately parting the hand.

*(Non-blocking telemetry notes observed during audit for completeness: in `30-card` and `14-card` compressed hands, `.hand-slot` width is `100px` while exposed strips are `19.04px` and `42.46px`, so targeting the `50px` center of an overlapped card physically lands on the overlapping neighbor to its right; `qa-table-collapse-right` starts with 4 `tablePairs` on the felt and allows both `7♣` and `8♥` sequentially; and the `HIGHLIGHT_SIZE_MISMATCH` warnings on `surrender-button` (`50x50` button with `30x30` SVG) and `throw-in-outline` (`100x140` card slot with `40x57` `+` SVG) reflect intentional button padding and card-sized drop-zone geometry.)*

## Required Changes

1. **`frontend/src/components/GameTable.tsx`:**
   - Update `partDirection` computation (around lines 3412–3419):
     - When `dragCard === null`, set `partDirection` from `deltaX`:
       - `deltaX < 0 ? 'left' : deltaX > 0 ? 'right' : 'none'`
       - This ensures single-card hands, resting cards, the hovered card (`deltaX === 0`), and distant unmoved cards all expose `data-part-direction="none"`, while left/right hover-parted neighbors expose `"left"` / `"right"`.
     - When `dragCard !== null`, preserve `index === draggedIndex ? undefined : reorderIndex === null ? 'none' : effectiveIndex < reorderIndex ? 'left' : 'right'` so existing drag-source unit tests (`frontend/src/__tests__/GameTable.test.tsx` lines 3935, 3991, 3999, 4122) continue to pass unchanged.
   - Remove `onPointerEnter={handleHandPointerMove}` from `[data-zone="player-hand"]` (line 3274), keeping `onPointerMove={handleHandPointerMove}` and `onMouseMove={handleHandPointerMove}` so a stationary pointer after lobby navigation/mount does not trigger hover-parting.
   - In `handleHandPointerMove` (lines 1721–1751), when `handRef.current` has a non-zero bounding rect (`rect.width > 0 && rect.height > 0`) and the event carries finite `clientY`, ignore moves outside the card row's vertical bounds (`clientY < rect.top - SELECTED_LIFT_PX || clientY > rect.bottom`) so moving over `.hand-clock` or `--hand-timer-clearance` does not part the cards (while preserving zero-rect JSDOM unit-test compatibility).

2. **`frontend/src/styles/table.css`:**
   - Remove the `.hand-card-wrapper[data-part-direction='none'] { transform: none; }` rule (lines 2712–2714) so `data-part-direction="none"` remains purely a declarative DOM hint and never conflicts with lifted card `translate3d(0px, -liftPx, 0)` transforms.
