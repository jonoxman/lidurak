## Implementation Spec

### 1. Engine helpers (`GameEngine.scala`)
Add two public methods:

```scala
def legalThrowInCards(state: GameState, playerId: String): List[Card]
def throwInCapacity(state: GameState, playerId: String): Int
```

- Both return `Nil` / `0` when any of these is true:
  - the player is unknown
  - the player is not `isActive`
  - the player has an empty hand
  - the player index is `state.defenderIdx` (the **defender never qualifies**)
  - `player.hasPassed == true`
  - `state.boutPhase` is not `Defense` or `SurrenderThrowIn`
  - `state.tablePairs.isEmpty`
  - `state.isGameOver`
  - the remaining throw-in capacity is `0`
- `throwInCapacity` must equal **exactly** the largest number of cards that `applyThrowInCards` will accept in one action right now.
  - Refactor the capacity math already inside `applyThrowInCards` into one private helper (e.g. `remainingThrowInSlots(state)`). Both methods must call it, so the two can never drift apart.
  - That helper covers `maxBoutAttacks - tablePairs.size` and any defender-hand-size limit the engine already enforces.
- `legalThrowInCards` = the player's hand cards whose rank is in `state.tableRanks`. Return it only when capacity > 0, in hand order.

### 2. Atomic multi-card throw-in (`applyThrowInCards`)
`GameAction.ThrowInCards(playerId, cards: List[Card])` must accept **1..capacity** cards in a single action.

It is **accepted** only when:
- the list is non-empty
- there are no duplicate cards
- every card is in the player's hand
- every card's rank is in `state.tableRanks` **as of before the action**
- `cards.size <= throwInCapacity(state, playerId)`
- the player is not the defender and has not passed

Any violation returns `Left(...)` and changes **no** state. There are no partial throw-ins.

The resulting state must be **identical** to applying the same cards one at a time, in list order, as single-card `ThrowInCards` actions. This includes:
- the same `boutPhase` transitions
- the same `hasPassed` resets
- the same `turnDeadlineMs` handling
- in the `SurrenderThrowIn` phase, the same taken-pile placement

`candidateActions` may keep listing single-card throw-ins (bots are unaffected). `GameReplay.verifyReplay` must still replay multi-card actions correctly.

### 3. View fields (`PlayerGameView.scala`)
Add these fields to `PlayerGameView` and populate them in `PlayerGameView.forViewer` for the viewing player:
- `throwInCards: List[Card] = Nil` → `GameEngine.legalThrowInCards(state, viewerId)`
- `throwInCapacity: Int = 0` → `GameEngine.throwInCapacity(state, viewerId)`
- `canThrowIn: Boolean = false` → `throwInCards.nonEmpty && throwInCapacity > 0`

In `reviewMode` (game over / replay frozen views), all three must be empty / `0` / `false`.

### 4. JSON (`JsonCodecs.scala`)
- Encode the fields as `"throwInCards"`, `"throwInCapacity"`, `"canThrowIn"`.
- Decode them as optional with defaults `[]`, `0`, `false`, so older payloads still decode.
- The `ThrowInCards` action decoder must accept a `cards` array of any length ≥ 1.

### 5. New 1-Click QA Scenario Presets
Register these presets next to `surrender-half-off` and `3p-redirect-bob`, using the same creation API and response shape (game id + default POV player id).

Rules for every preset:
- All seats are **human** (hotseat), so no bot acts.
- Cards are deterministic.
- Each preset conserves the deck exactly: hands + table + talon + discard = full deck, with no duplicates.
- The turn clock behaves like the existing presets.

| Preset id | Players / deck | Exact state | Default POV |
|---|---|---|---|
| `throw-in-visibility-4p` | 4P, 52 cards, trump ♣ | `attackerIdx=0`, `defenderIdx=1`, phase `Defense`, table `7♠` covered by `9♠`, `defenderInitialHandSize=7`. See the hand list below. | Alice `p0` |
| `throw-in-capacity-cap` | 2P, 36 cards, trump ♣ | Phase `Defense`, table `7♠` covered by `9♠`, `defenderInitialHandSize=3`, so capacity = **2**. See the hand list below. | Alice `p0` |
| `huge-hand-36` | 2P, 36 cards, trump ♥ | Talon empty, discard empty. Alice `p0` attacker holds `6♦`. Table: `6♠` uncovered, phase `Defense`. Bob `p1` defender holds **all 34 remaining cards**. | Bob `p1` |
| `huge-hand-52` | 4P, 52 cards, trump ♥ | Talon empty. Alice `p0` attacker holds `2♦ 3♦`. Table: `2♠` uncovered, phase `Defense`. Bob `p1` defender holds **all 46 remaining cards**. Carol `p2` holds `4♦ 5♦`. Dave `p3` holds `6♦`. | Bob `p1` |

Hands for `throw-in-visibility-4p`:
- **Alice** (attacker, POV): `7♥ 7♦ 9♦ K♠ Q♥ 6♣`. Legal throw-ins: `7♥ 7♦ 9♦`.
- **Bob** (defender): `9♥ 10♦ J♠ 8♥ 6♦ A♦`. He holds a matching 9 but must still never qualify.
- **Carol**: `8♠ 10♣ J♥ Q♦ K♦ A♠`. No 7s or 9s.
- **Dave**: `7♣ 8♦ 10♥ J♦ Q♠ K♥`, with `hasPassed=true`.
- Talon: the remaining 26 cards, ending with a ♣ bottom trump.

Hands for `throw-in-capacity-cap`:
- **Alice** (attacker, POV): `7♥ 7♦ 7♣ 9♦ K♠ Q♥`. That is 4 legal throw-ins against a capacity of 2.
- **Bob** (defender): `8♥ 10♦`.
- Talon: the remaining cards.

## Required Tests (add or update)
- **`ThrowInEligibilitySuite`**, using the `throw-in-visibility-4p` state:
  - Alice → `throwInCards == List(7♥, 7♦, 9♦)` and `canThrowIn == true`.
  - Bob (defender, holds `9♥`) → empty / `false`.
  - Carol (no matching ranks) → empty / `false`.
  - Dave (passed, holds `7♣`) → empty / `false`.
  - After Alice passes → Alice is empty / `false`.
- **Capacity property:** for every k in `1..throwInCapacity`, throwing k legal cards in one action succeeds. k+1 fails with an unchanged state. `throw-in-capacity-cap` → capacity `2`, and 3 cards are rejected.
- **Atomicity:** a 3-card `ThrowInCards` where one card is illegal → `Left`, and the state is unchanged.
- **Equivalence:** a multi-card throw-in gives the same state as the same cards thrown one by one. Check this in the `Defense` and `SurrenderThrowIn` phases.
- **JSON round-trip:** the new view fields round-trip. A legacy payload without them decodes to the defaults. A multi-card `ThrowInCards` round-trips.
- **`PresetSuite`:** all 4 presets create successfully. Check the exact hands, phase, `hasPassed`, capacity and card conservation (36 or 52 unique cards).
- `GameReplaySuite` still passes with a recorded multi-card throw-in.
