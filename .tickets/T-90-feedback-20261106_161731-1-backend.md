## Context
Wave 3 (T-5) will show the additional-card outline (`[data-testid="throw-in-outline"]`) **only when `view.canThrowIn === true`**. It will also add multi-select plus double-click to throw in several cards at once. The backend must therefore:
1. Calculate `canThrowIn` exactly and per viewer.
2. Accept a multi-card `GameAction.ThrowInCards(playerId, cards)` atomically.
3. Provide 1-click QA presets so a human can verify the feature within 15 seconds.

## Implementation Spec

### A. `canThrowIn` / `throwInCards` / `throwInCapacity` in `PlayerGameView.forViewer`
- `throwInCards` (per viewer) = the viewer's hand cards whose rank is in `state.tableRanks`. It is an **empty list** when any of these is true:
  - the viewer is the defender (`state.defenderIdx`)
  - the viewer has passed (`player.hasPassed`)
  - the viewer is inactive or finished (`!player.isActive`)
  - `state.boutPhase` is not `Defense` or `SurrenderThrowIn`
  - `state.tablePairs` is empty
  - the game is over or the view is `reviewMode` (replay)
- `throwInCapacity` keeps its existing calculation of remaining legal slots. Do not redefine the throw-in limit rules.
- `canThrowIn` = `throwInCards.nonEmpty && throwInCapacity > 0`. It must also be consistent with `GameEngine.legalActions(state, viewerId)`: if `canThrowIn` is true, at least one `ThrowInCards(viewerId, List(card))` must be legal. If no `ThrowInCards` is legal, `canThrowIn` must be false.
- Replay frames (`GameReplay.frozenViews`) must output `canThrowIn = false` once the game is over or the view is in review mode.

### B. Multi-card `ThrowInCards`
- `GameEngine.applyThrowInCards(state, playerId, cards)` must accept `cards.size >= 1` up to `throwInCapacity`. The rules:
  - every card is in the player's hand, with no duplicates
  - every card's rank is in the table ranks
  - the player is not the defender and has not passed
  - the phase is `Defense` or `SurrenderThrowIn`
- It is **atomic**: if any card is invalid, or the count is over capacity, the whole action returns `Left(...)` and the state is unchanged.
- It must work in both phases. In `SurrenderThrowIn`, the thrown-in cards join the "being taken" set exactly as single-card throw-ins do today.
- Turn-clock behavior after a multi-card throw-in must match a single-card throw-in (extend `ThrowInClockSuite`).
- `candidateActions` / `legalActions` may keep listing single-card throw-ins (bots are unaffected). Do not change `BasicBot`/`RandomBot` behavior.
- Make sure the WebSocket/route action decoder accepts `{"type": "ThrowInCards", "playerId": ..., "cards": [c1, c2, c3]}`, or whatever the existing envelope shape is. Add a `JsonCodecsSuite` / `GameRoutesSuite` round-trip test.

### C. New 1-Click QA Scenario Presets
Add them next to the existing presets, using the same ID convention, creation route and POV mechanism. Each preset must create a live, legal, card-conserving game state: the total cards across hands, table, talon and discard must equal the deck size.

1. **`throw-in-visibility-3p`**, label "Throw-In Visibility (3P)". 3 players, all human/hotseat. Phase `Defense`.
   - Alice `p0` is the attacker. One uncovered attack, `7♠`, is on the table.
   - Bob `p1` is the defender. He holds at least 4 cards, including one card that can legally cover `7♠` (for example `9♠`).
   - Alice's hand contains `7♥` plus other cards that do not match any table rank.
   - Carol `p2`'s hand contains **no** 7s and none of the ranks Bob can cover with, so she never has a legal throw-in.
   - The talon is non-empty. The default POV is Alice.
   - Expected `canThrowIn`: Alice = true, Bob = false (defender), Carol = false (no valid cards), Alice after `PassTurn` = false (passed).
2. **`multi-throw-in`**, label "Multi Throw-In". 2 or 3 players. Phase `Defense`.
   - Alice is the attacker. `7♠` is on the table.
   - Alice holds `7♥`, `7♦`, `7♣` plus 2 or more unrelated cards.
   - Bob, the defender, holds at least 5 cards so that `defenderInitialHandSize` ≥ 4 and `throwInCapacity` ≥ 3. At least one of his cards can cover `7♠`. He can also surrender, which lets you test the surrender-phase multi throw-in.
   - The default POV is Alice.
3. **`full-hand-4p`**, label "Full Hand (4P)". 4 players, 52-card deck. Phase `Defense`.
   - Bob `p1` (default POV, "Bob (You)") is the defender and holds **40 cards**. Several of them can legally cover the single uncovered attack on the table, so they render raised as playable. Several cannot.
   - Alice `p0` (attacker) holds 4 cards, Carol 3, Dave 3. There is 1 attack card on the table, and the talon holds exactly 1 card (the bottom trump). 40 + 4 + 3 + 3 + 1 + 1 = 52.
   - This preset is used to verify hand overlap, wrapping and the outline at maximum hand size.
- Each preset must show up in the "⚡ QA Scenarios" selector in **both** the Lobby (`LobbyPage.tsx`) and the left sidebar (`GamePage.tsx` `[data-zone="sidebar-left"]`), reusing the existing preset mechanism. If the catalog is served by a backend endpoint, add the entries there. If it is hardcoded in the frontend, add list entries only (see Files Owned).
