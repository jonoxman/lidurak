# T-95-2: Wire Milestone 1 Gameplay Interface for Multiplayer, Remove Placeholder UI & Fix Constant-Width Hand Hover Animation

## Background & Gap
1. Multiplayer matches (`/g/:gameId`) currently render a lightweight Milestone 2 placeholder gameplay view instead of the full Milestone 1 gameplay interface (`GamePage`, `GameTable`, card interactions, defender-anchored target outlines, redirect arrow outline, SortBar, contextual Surrender/Pass button, 3-column Lichess shell, turn clock, and game-over summary). The lightweight placeholder interface must be completely removed from the project, and all multiplayer gameplay must use the original Milestone 1 gameplay interface.
2. In the Milestone 1 gameplay hand animation, hovering over cards when the active user's hand is small enough not to fill the maximal allowed width currently increases the overall width of the hand. The hand's total rendered width must remain constant during mouseover—only spreading cards apart around the hovered card and compressing/pushing adjacent cards together within the constant width.

## Requirements
1. **Integrate Full Milestone 1 Gameplay Interface for Multiplayer Routes (`/g/:gameId`):**
   - Route `/g/:gameId` in `frontend/src/app.tsx` to render the unified Milestone 1 `GamePage` (or a thin multiplayer data/socket adapter feeding directly into the Milestone 1 `GamePage` / `GameTable` components) while keeping legacy `#/g/:gameId?player=:seat` local/bot routes fully functional.
   - Bridge the multiplayer `PlayerGameView` and `/ws/games/:gameId` socket (`gameSocket.ts`) to the Milestone 1 gameplay interface:
     - **Strict Anti-Cheat Zero-Leak Preserved:** Ensure backend multiplayer `PlayerGameView` projection continues to omit opponent card identities and undealt talon cards (and returns `hand: []` / `viewerSeat: null` for spectators), while exposing any non-secret public fields needed by the Milestone 1 `GameTable` (e.g., `tablePairs`, `talonCount`, `bottomTrumpCard`, `trumpSuit`, `discardCount`, `lastDiscardCards`, `attackerIdx`, `defenderIdx`, `boutPhase`, `legalActions`, `turnDeadlineMs`, `turnSecondsRemaining`, `defenderDefenseless`, `allowRedirect`, `maxBoutAttacks`, `finishOrder`, `winners`, `durak`, `isDraw`, `promptedPlayerIds`, `eligibleTargetIds`, `redirectTargetId`).
     - Map all Milestone 1 player interactions (initial attack, cover card on target outline, redirect attack on redirect outline, throw-in cards, surrender, pass) to multiplayer WebSocket `PlayerAction` frames when in multiplayer mode.
     - Preserve the strict Lichess 3-column desktop shell (`[data-zone="sidebar-left"]`, `[data-zone="table-arena"]`, `[data-zone="sidebar-right"]`) with CSS Grid/Flexbox (no `position: absolute`/`fixed` layout overlaps) and zero table text clutter during active play.
     - Handle `WaitingForPlayers` rooms cleanly inside the Milestone 1 layout (e.g., displaying occupied/open seats, shareable `/g/<gameId>` invite link with copy button, `"Join"` CTA for unseated viewers calling `POST /api/games/:gameId/join`, and `"Leave"` CTA for seated players calling `POST /api/games/:gameId/leave` in the sidebar/waiting panel, transitioning seamlessly into live card play once `InProgress`).
     - Handle spectator views (`viewerSeat: null`) cleanly in the Milestone 1 table layout with zero hand cards rendered and read-only controls (plus a `"Join"` option only when the room is `WaitingForPlayers` and has an open seat).
     - Ensure all existing QA Scenario Presets (`Launch active projected match`, `Launch spectator zero-leak view`, `Launch 2P invite room (1/2)`) open into the full Milestone 1 gameplay interface.

2. **Completely Remove Lightweight Placeholder Gameplay Interface:**
   - Delete `MultiplayerGamePage.tsx` (and any M2-only placeholder gameplay subcomponents, placeholder CSS files/rules, and placeholder-only test files) so zero dead placeholder gameplay code remains in `frontend/src/`.
   - Remove all stale imports and references to the removed placeholder page across the codebase.

3. **Constant-Width Hand Mouseover Animation (Milestone 1 HandZone / `table.css`):**
   - Inspect the active player's hand layout and hover animation in `[data-zone="player-hand"]` (e.g., `HandZone.tsx`, `GameTable.tsx`, `table.css`).
   - When the active player's hand has fewer cards than needed to fill the maximum allowed hand width, compute/constrain the hand container's width and per-card hover translation/spacing offsets so that:
     - The outer left edge of the leftmost card and the outer right edge of the rightmost card **do not move outward** on mouseover—i.e., the total width of the hand stays strictly constant whether hovering any card or not hovering at all.
     - Hovering a card only redistributes space *inside* that constant total width (spreading cards immediately adjacent to the hovered card and pushing remaining cards closer together as needed, without ever growing the overall hand width).
     - If a hand has 1 card, hovering it lifts/highlights it vertically without changing horizontal width.
     - Full/large hands that already fill the max allowed width continue to spread smoothly within the max allowed width without overflow.
