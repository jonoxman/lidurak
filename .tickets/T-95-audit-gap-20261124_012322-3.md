# T-95-3: Lobby Quick Pairing Tile Height, "Create a Game" Rename/Reorder & Milestone 1 Design/Theme Integration

## Background & Gap
The newly added Milestone 2 lobby UI elements currently use hardcoded dark-only Milestone 2 colors (`#161512`, `#262421`, `#bababa`, etc.) instead of adopting the Milestone 1 design system and responding to the profile menu theme selector. Additionally:
- The Quick Pairing tiles need to be approximately double their current height while preserving their layout.
- The third lobby section currently named `"Create Invite Link"` must be renamed to `"Create a Game"` and rearranged so that choosing whether the game is a private link or public is the first option, followed by the remaining options in their current order.

## Requirements
1. **Double-Height Quick Pairing Tiles (Same Layout):**
   - In `frontend/src/styles/lobby.css` (and `QuickPairingTab.tsx` if needed), increase the height of the Quick Pairing preset tiles (`[data-testid="quick-pair-*"]`) to approximately **double** their current height (e.g., doubling `min-height` and adjusting vertical padding/centering cleanly).
   - Keep the existing grid layout (`2P/3P/4P` x `15s/30s` tiles) and internal text hierarchy intact with zero overlap and zero horizontal overflow.

2. **Rename "Create Invite Link" to "Create a Game" & Rearrange Controls:**
   - Rename the third lobby tab label, section `aria-label`, heading, and any internal labels from `"Create Invite Link"` to `"Create a Game"`.
   - Rearrange the form inside this section so that the **first choice** is whether the game is a **private link or not** (e.g., `Visibility` / `Private invite link` vs `Public lobby pool` toggle/segmented control), followed by the remaining options in their exact current order:
     1. Private link / visibility choice (FIRST)
     2. Player count (`2`, `3`, `4` players + deck size note `"36-card deck"` / `"52-card deck"`)
     3. Redirect / reflect toggle (`Redirect / reflect: ON/OFF`)
     4. Turn clock (`15s`, `30s`, `60s`, etc.)
     5. Submit button (`Create room` / `Create game`)
   - Preserve existing accessible labels (`aria-label="4 players"`, `role="group"`, etc.) and ensure creating both private and public games still works end-to-end.

3. **Adopt Milestone 1 Design Style & Full Profile-Menu Theme Responsiveness:**
   - Audit all newly created Milestone 2 lobby components and `frontend/src/styles/lobby.css` (tabs, `.m2-panel`, Quick Pairing tiles, searching banner, Lobby Pool list/rows/badges/empty state, Create a Game form/segmented controls/toggles/buttons, QA Scenario Presets panel, guest identity/rename controls).
   - Replace hardcoded Milestone 2 hex colors (`#161512`, `#262421`, `#bababa`, `#629924`, `#c33`, etc.) with the Milestone 1 CSS custom properties/tokens, typography, surface elevation, borders, radii, and button/input styling so the lobby matches the Milestone 1 aesthetic seamlessly.
   - Ensure the profile menu (including theme selection) is accessible and wired consistently on `LobbyPage`, and verify that switching themes in the profile menu dynamically updates every lobby element (background, panel surfaces, text, muted text, borders, active tab indicators, Quick Pairing tiles, Lobby Pool rows & badges, Create a Game controls, QA Scenario Presets panel, and buttons) with readable contrast across **every** available theme.
   - Maintain strict CSS Grid/Flexbox layout (`gap`, `min-width: 0`, `box-sizing: border-box`) with zero `position: absolute`/`fixed` layout positioning and zero horizontal overflow.
