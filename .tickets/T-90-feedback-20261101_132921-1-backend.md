## Summary
Implement all backend support required for the current feedback batch:
1. Add a server readiness health endpoint (`GET /api/health`) so the frontend can wait for the server to finish starting before allowing game creation.
2. Fix the `org.http4s.ember.server` 60-second `java.util.concurrent.TimeoutException` on WebSocket connections by adding server-side WebSocket keepalive frames (`Ping` / heartbeat), handling incoming client ping/pong/presence frames cleanly, and configuring Ember server idle timeout appropriately.

## Detailed Requirements

### 1. Server Readiness Health Endpoint (`GameRoutes.scala`)
- Add `GET /api/health` in `GameRoutes.routes` returning HTTP `200 OK` with JSON `{"status": "ok"}`.

### 2. Fix WebSocket 60-Second `TimeoutException` (`Main.scala`, `GameRoutes.scala`, `GameActor.scala`)
- **Root Cause:** `EmberServerBuilder.default[IO]` uses a default 60-second `idleTimeout`. When a WebSocket connection has no frames flowing for 60 seconds (e.g., after a game ends or while idle), Ember terminates the WebSocket with `java.util.concurrent.TimeoutException: 60 seconds`.
- **Fixes Required:**
  1. In `Main.scala`, configure `EmberServerBuilder.default[IO]` with a generous `.withIdleTimeout(10.minutes)` (from `scala.concurrent.duration.*`).
  2. In `GameRoutes.scala`, merge the outbound WebSocket `Stream[IO, WebSocketFrame]` with a periodic keepalive stream (`fs2.Stream.awakeEvery[IO](20.seconds).map(_ => WebSocketFrame.Ping())`) so the connection never sits idle.
  3. In the WebSocket receive pipe in `GameRoutes.scala`:
     - Handle `WebSocketFrame.Ping(_)` and `WebSocketFrame.Pong(_)` gracefully without throwing errors or closing the stream.
     - Handle `WebSocketFrame.Text(text, _)`:
       - Parse JSON control messages:
         - If `{"type": "ping"}` -> no-op / keepalive acknowledgement.
         - If `{"type": "presence", "isPresent": true|false}` (or `"active": true|false`) -> update the player's presence status in `GameActor` (`actor.setPresence(playerId, isPresent)`).
         - Otherwise, if it is a `GameAction`, process it via `actor.submitAction(action)` as before.
     - On WebSocket disconnect (`onFinalize`), mark that human player's presence as `false` in `GameActor`.

### 3. `RandomBot` Agent & Per-Player Type Configuration (`GameConfig.scala`, `JsonCodecs.scala`, `GameRoutes.scala`, `GameActor.scala`)
- **`GameConfig` (`GameConfig.scala`):**
  - Add `playerTypes: Vector[String] = Vector.empty` with a default value so existing calls to `GameConfig(playerCount, playerNames, allowRedirect, chaosMode)` remain 100% source-compatible.
  - Provide a helper `def isBotSeat(seatIdx: Int): Boolean` (returns `true` when `playerTypes.lift(seatIdx).exists(t => t.equalsIgnoreCase("randomBot") || t.equalsIgnoreCase("bot"))`).
- **`CreateGameRequest` (`GameRoutes.scala` & `JsonCodecs.scala`):**
  - Accept optional `playerTypes: Option[Vector[String]] = None` in `POST /api/games` (and `/api/game/create` if aliased).
  - Normalize `playerTypes` to length `playerCount` (defaulting any missing entry to `"human"`).
- **`RandomBot` Move Selection:**
  - Implement a deterministic/testable legal-move enumeration helper (e.g., `RandomBot.legalActionsFor(state: GameState, playerId: String): Vector[GameAction]` and `RandomBot.chooseAction(state: GameState, playerId: String, rng: scala.util.Random = new scala.util.Random()): Option[GameAction]`):
    - If `state.boutPhase == BoutPhase.GameOver`, return `Vector.empty`.
    - Generate all candidate `GameAction`s for `playerId` based on their hand and the current `state`:
      - `InitialAttack(playerId, card, targetOpt)` (for all cards in hand; in `chaosMode`, across all active opponent targets with cards; in standard mode, `None`).
      - `CoverCard(playerId, pairIdx, card)` (for all uncovered `tablePairs` indices and all cards in hand).
      - `RedirectAttack(playerId, card)` (if `state.config.allowRedirect`, for all cards in hand).
      - `ThrowInCards(playerId, Vector(card))` (for all cards in hand).
      - `PassTurn(playerId)`.
      - `DeclareSurrender(playerId)` ( note: if the bot is defending and has at least one valid `CoverCard` or `RedirectAttack`, you may either include `DeclareSurrender` in the random pool or include all legal actions that `GameEngine.process(state, action).isRight` accepts — ensure every returned action satisfies `GameEngine.process(state, action).isRight`).
    - Filter all candidate actions by `action => GameEngine.process(state, action).isRight`.
    - `chooseAction` picks one action uniformly at random from the non-empty legal actions vector.
- **Bot Delay Scheduling in `GameActor.scala`:**
  - Whenever a game is created or transitions to a new state (and `state.boutPhase != BoutPhase.GameOver`), check if any bot player (`state.config.isBotSeat(idx)`) currently has non-empty legal actions via `RandomBot.legalActionsFor(state, botId)`.
  - Priorities:
    - During `BoutPhase.Attacking`, the active attacker (`state.attackerIdx`) is the prompted player.
    - During `BoutPhase.Defending`: if there are uncovered table pairs, the defender (`state.defenderIdx`) is prompted first; once all pairs are covered (or during `BoutPhase.Surrendered`), any unpassed attacker who is a bot is prompted to throw in or pass.
  - When a bot is prompted to act, spawn a background fiber that waits a random delay between `500.millis` and `2000.millis` (configurable in `GameActor` constructor for fast unit testing, defaulting to `500ms..2000ms`), then selects a random legal move via `RandomBot.chooseAction` and applies it through the actor's action submission pipeline.
  - Cancel any pending bot fiber whenever a new state transition occurs so stale moves never execute.

### 4. Player Presence Tracking (`PlayerGameView.scala`, `JsonCodecs.scala`, `GameActor.scala`, `GameRoutes.scala`)
- In `OpponentView` (`PlayerGameView.scala`), add `isPresent: Boolean = false`.
- In `PlayerGameView` (`PlayerGameView.scala`), add `presentPlayers: Vector[String] = Vector.empty` (list of player IDs currently marked present, e.g. `Vector("p0", "p1")`).
- In `GameActor.scala`:
  - Maintain `presentPlayers: Set[String]` in the actor state.
  - Bot players (`isBotSeat(idx) == true`) are always considered present (`true`) while active in the game.
  - Human players are marked present (`true`) when they report active presence via WebSocket (`{"type": "presence", "isPresent": true}`) or REST (`POST /api/games/:gameId/presence` with `{"playerId": "p0", "isPresent": true}`), and marked `false` when they report `isPresent: false` or disconnect.
  - Broadcast updated `PlayerGameView` snapshots to subscribers whenever `presentPlayers` changes.
