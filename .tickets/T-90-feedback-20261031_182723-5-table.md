# Ticket T-90-feedback-20261031_182723-5: Game Table Arena, Player Seats, Individual Clocks, Fixed Order, Attacker/Defender Highlights, and Spatial Rules

## Subsystem
Frontend Game Arena (`frontend/src/components/GameTable.tsx`, `frontend/src/pages/GamePage.tsx`, `frontend/src/styles/table.css`)

## Wave
WAVE:2 (Builds on Wave 1 Card Visuals and Backend Clock; runs concurrently with Ticket 4)

## Description & User Requirements
Refactor the table arena layout, player seats, turn clocks, and selection highlights in strict accordance with the Lichess 3-column architecture and zero text-clutter rules:
1. **T-Shape Deck and Trump Suit Display (Feedback Item 1)**:
   - In `[data-zone="table-deck"]`, render the talon deck and the face-up trump card in an overlapping T-shape (trump card turned 90 degrees partially underneath the perpendicular deck pile) instead of placed adjacent to each other.
2. **Fixed Order in Hotseat & Players List (Feedback Item 13)**:
   - In the Hotseat switcher tabs (`[data-zone="sidebar-left"]`), DO NOT reorder players to put the active player at the top; keep player order fixed by seat index (`p0`, `p1`, `p2`, ...).
   - In the Players list on the right sidebar (`[data-zone="sidebar-right"]`), keep player positions similarly fixed in seat order.
3. **Individual Player Turn Clocks Above Player Boxes (Feedback Item 14)**:
   - Display each player's digital countdown clock in a clean, small format positioned directly above each player's box (where their card deck/hand is held), in addition to the main active turn clock in the right sidebar.
   - Show the countdown ticking down whenever that player is being waited on to act.
4. **Equal Opponent Box Sizes (Feedback Item 15)**:
   - Ensure all opponent player boxes (`[data-seat="top-left"]`, `[data-seat="top-center"]`, `[data-seat="top-right"]`) have strictly identical CSS Grid/Flexbox dimensions (`min-width: 0`, uniform width/height) so no seat appears larger or smaller than others.
5. **Styled "Back to Lobby" Button (Feedback Item 17)**:
   - Convert the "Back to lobby" link in the top right of the game page into a styled `<button>` element matching the site's action button aesthetic.
6. **Strict Text Highlight Prohibition (Feedback Item 20)**:
   - Prevent text highlighting anywhere in the game elements using `user-select: none; -webkit-user-select: none;`.
   - This applies to all play area surfaces, cards, buttons, outlines, and timers.
   - The ONLY allowed exceptions where text may be selected are: the Game ID, the "HOW TO PLAY" section, and the players' display names.
7. **Distinct Attacker vs. Defender Highlights (Feedback Item 21)**:
   - Use two distinctly different colors to highlight the player about to attack and the player about to be attacked (e.g., golden amber for attacker; crimson / rose for defender).
   - The color used for the attacking player's seat highlight must match the highlight color of their hand.
8. **Tight-Fitting Attacker Hand Box (Feedback Item 22)**:
   - Tighten the highlight bounding box around the active player's hand (`[data-zone="player-hand"]`) when attacking, eliminating excessive whitespace so it closely hugs the cards.
9. **Zero-Overlap Architecture Compliance (Agents Rules)**:
   - Strictly maintain zero-overlap CSS Grid (`min-width: 0; box-sizing: border-box; gap: ...`). Never use `position: absolute` or `fixed` for placing seats, sidebars, or bouts.
   - Zero table text clutter: never render status banners like "Waiting for first attack..." or invalid move error messages on the table felt.
