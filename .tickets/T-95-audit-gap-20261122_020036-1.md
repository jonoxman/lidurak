# T-95-audit-gap-1: Verify & Remediate Card Sizing, Active Hand Overlap, Non-Rectangular Hand Contour, and Drag Visibility

## Context
During the pre-release audit of `main`, the frontend source files for card sizing, active player hand overlap, responsive non-rectangular hand highlight contour, and drag visibility were truncated from the audit diff. Inspect the current working tree first (`git status` / `git diff` and reading the existing frontend files) — preserve any working implementation and fix every remaining gap or unwired detail below.

## Requirements

1. **Card Dimensions Match Outlines (QA Playbook #2):**
   - Ensure actual playing cards rendered on the table (attacks, covers, redirects) and in the active player's hand match the larger dimensions of `[data-testid="throw-in-outline"]` and `[data-testid="redirect-outline"]` (exact same width, height, and border radius across desktop and mobile breakpoints), driven by shared CSS custom properties / layout rules with no smaller legacy card size overrides.

2. **Active Hand Dynamic Card Overlap (New #3):**
   - Arrange cards in `[data-zone="player-hand"]` so adjacent cards overlap by **~20% of card width at minimum** and **~80% of card width at maximum** (tuned so the left-side rank symbol and suit pip remain clearly visible on every card).
   - Ensure that even when a player holds an extreme hand (30 cards in `large-hand-stress`, 34 cards in `huge-hand-36`, or 46 cards in `huge-hand-52`), the hand remains cleanly contained within `[data-zone="player-hand"]` without overflowing off-screen or overlapping the talon deck (`[data-zone="table-deck"]`) or bottom-right action controls.

3. **Responsive Non-Rectangular Hand Highlight Contour (New #1):**
   - Replace/ensure the active player's hand highlight does not rely on a misaligned static rectangular box.
   - The highlight outline must tightly wrap the actual rendered positions of every card in the active player's hand at all times, dynamically distorting into a non-rectangular contour whenever individual playable/selected cards are shifted upward, and updating accurately whenever hand size, overlap, viewport width, or playable-card lift states change (coordinated with New #3).

4. **Card Remains Visible While Dragged (New #2):**
   - Ensure clicking and dragging any card from the active player's hand NEVER makes the card invisible (`opacity: 0`, `visibility: hidden`, `display: none`, or removing the rendered card while dragging).
   - Cards must remain continuously visible (aside from normal overlap rules) throughout pointer/drag interaction from mousedown/dragstart through drop/dragend.

- Add or verify Vitest tests covering:
  1. Card dimensions matching `[data-testid="throw-in-outline"]` and `[data-testid="redirect-outline"]`.
  2. Dynamic hand overlap staying within the ~20%–80% bounds across small hands (2–6 cards) and stress hands (30 / 34 / 46 cards) without overflowing container width.
  3. Non-rectangular hand contour geometry tracking actual card bounding boxes and stepping upward around raised playable cards.
  4. Dragging a card keeping the card visible throughout the drag lifecycle.
- Run `cd frontend && npm test -- --run` and ensure all tests pass with zero failures.
