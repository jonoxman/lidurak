# T-95-audit-gap-20261124_015718-3: Integrate Full Milestone 1 Gameplay Interface for Multiplayer, Remove Placeholder UI, & Constant-Width Hand Hover Animation

## Background & Gap
Human feedback (New #3 and #4) requires:
1. Hooking the original Milestone 1 gameplay interface (`GamePage`, `GameTable`, `table.css`, Lichess 3-column felt table, opponent seats, bout cards, defender-anchored target outlines, redirect arrow outline, talon/trump deck, SortBar, Surrender/Pass controls, digital `00:XX` turn clock, results/Durak display, and M1 theme support) into **all** gameplay views — including Milestone 2 multiplayer routes (`/g/:gameId`) — and **completely removing** the lightweight placeholder interface (`MultiplayerGamePage` and its associated files/styles/imports).
2. Fixing the Milestone 1 active player hand mouseover animation so that when a hand is small enough not to fill the maximal allowed width, hovering over cards **never** increases the overall rendered width of the hand — instead, cards only spread apart and push together within that constant outer width.

## Scope & Requirements
1. **Complete Removal of Lightweight Placeholder Interface:**
   - Locate and delete `MultiplayerGamePage.tsx` (and any dedicated placeholder stylesheet, helper modules, or placeholder-only tests).
   - Remove all imports, router branches, and references to the placeholder component from `frontend/src/app.tsx` and anywhere else in the repo.

2. **Wire Milestone 1 Gameplay Interface to All Multiplayer & Local/Bot Routes:**
   - Update `frontend/src/app.tsx` so `/g/:gameId` (History API multiplayer route) renders the unified Milestone 1 `GamePage` (alongside existing M1 `#/g/:gameId?player=:seat` local/bot hash routes).
   - Build a clean multiplayer controller/adapter inside `GamePage` (or a companion hook such as `useMultiplayerGame.ts`) that:
     - Hydrates state from `GET /api/games/:gameId` and subscribes to live updates via `gameSocket.ts` (`/ws/games/:gameId` with keepalive & reconnect).
     - Maps multiplayer `PlayerGameView` into the Milestone 1 `GameTable` / `GamePage` props so every gameplay action (InitialAttack, CoverCard, RedirectAttack, ThrowInCards, DeclareSurrender, PassTurn) dispatches typed WebSocket frames (`submitAction`) and renders live updates with zero table text clutter.
     - Handles `WaitingForPlayers` state cleanly inside the M1 3-column shell (e.g., displaying occupied/open seats, copyable invite link, Join button for unseated visitors, and Leave Room button for seated players while waiting, without violating Zero-Overlap CSS Grid rules or adding table clutter).
     - Handles Spectator mode (`viewerSeat === null`) cleanly in read-only mode (empty hand, opponent/player seats visible, zero leaked hidden cards).
     - Handles `Finished` / Game Over state with the M1 winner / Durak results in `[data-zone="sidebar-right"]` and return-to-lobby navigation.
   - **Backend `PlayerGameView` Projection Check (Anti-Cheat Preserved):**
     - Verify whether the M2 `PlayerGameView` serializer/projection in `backend/src/main/scala/durak/...` exposes all public/viewer-safe fields required by the Milestone 1 `GameTable` (e.g., `tablePairs`, `talonCount`, `bottomTrumpCard`, `trumpSuit`, `attackerIdx`, `defenderIdx`, `boutPhase`, `legalActions`, `maxBoutAttacks`, `discardCount`, `lastDiscardCards`, `turnPlayerId`, `turnDeadlineMs`, `turnSecondsRemaining`, `winners`, `durak`, `isDraw`, `finishOrder`, `promptedPlayerIds`, `eligibleTargetIds`, `redirectTargetId`, `allowRedirect`).
     - If any M1-needed non-secret fields are missing from the M2 `PlayerGameView` JSON, add them on the backend while **strictly preserving zero-leak anti-cheat guarantees**: opponents' card identities and undealt talon deck cards must NEVER appear in any seated player's or spectator's JSON payload.
   - Verify all existing QA Scenario Presets (`Launch active projected match`, `Launch spectator zero-leak view`, `Launch 2P invite room (1/2)`, `Seed open lobby pool`) continue to work end-to-end and launch directly into the full Milestone 1 gameplay interface.

3. **Constant-Width Hand Mouseover Animation for Small Hands (Milestone 1 Gameplay Interface):**
   - Inspect the Milestone 1 player hand layout and hover animation (`frontend/src/components/...` hand component / `GameTable.tsx` / `frontend/src/styles/table.css`).
   - Identify why hovering over a card in a small hand (a hand that does not fill the maximal allowed hand width) currently causes the total hand width to expand.
   - Update the hand card layout / hover displacement calculation so that for **every** hand size (both small hands that do not fill the max width and large hands at max width):
     - The outer bounding span of the hand (from the left edge of the first card to the right edge of the last card, and the hand container's width) remains **strictly constant** when any card is hovered.
     - On mouseover of card `i`:
       - For `n === 1`: no horizontal shift (vertical lift only; width invariant).
       - For `n === 2`: outer edges stay fixed (do not push the neighbor outside the original two-card span; vertical lift / z-index highlight only, or internal shift bounded strictly within `[0, restingWidth]`).
       - For `n >= 3`: keep card `0`'s left edge fixed at `0` and card `n - 1`'s right edge fixed at `restingWidth` (exact same total width as unhovered); spread immediate neighbors away from the hovered card `i` while proportionally compressing the spacing among the remaining cards on each side so the total span never grows by even 1px.
   - Ensure the animation remains smooth, cards remain easy to click/drag/play, and there is zero layout shift of surrounding Row 3 grid columns (`table-deck`, `player-hand`, `SortBar` / action button).
