# Fix Uncovered Table-Pair Padding Width Mismatch and Desktop `1280×800` Viewport Vertical Clipping

## Context & Observed Failures
- Real Chromium visual QA (`1280×800`) reported:
  - `Item 6: 30-card vertical clipping detected: card clipped outside viewport` (`[data-zone="player-hand"]` measured `y: 577, h: 270`, extending to `847px > 800px` viewport height; `[data-zone="table-arena"]` measured `y: 127, h: 830`, bottom `957px`, pushing Row 4 action buttons `y: 872..922` and `hand-sort-box` `y: 969..1050` below the fold).
  - `3x Failed to load resource: the server responded with a status of 400 (Bad Request)` on `POST /api/games/preset` for `qa-table-collapse-right` and `qa-surrender-timer` (screenshots `step_2` and `step_7`–`step_10` stayed on the lobby with `Unknown preset: ...`), because `.reviews/qa_backend.log` hit `java.net.BindException: Address already in use` and left an older backend process on port `8080` (even though `backend/src/main/scala/durak/server/GameManager.scala` already defines `QaTableCollapseRight` and `QaSurrenderTimer`).
- Code inspection of Item 1's table layout also uncovered an objective CSS/solver geometry mismatch on uncovered `.table-pair` elements that overflows `.battlefield-tinted-box` when multiple uncovered pairs share the row.

## Requirements

### 1. Fix Uncovered `.table-pair` Horizontal Padding Mismatch (`table.css` vs `tableLayout.ts`)
- **Problem:** In `frontend/src/styles/table.css`, `.table-pair` unconditionally sets `padding: 0 var(--pair-defense-offset, 36px) var(--bout-card-offset, 18px) 0;` with `box-sizing: border-box`. Every uncovered pair (`data-covered="false"`) therefore occupies `136px` in the DOM instead of `100px`, while `computeTableBoutLayout` in `frontend/src/utils/tableLayout.ts` (`uncoveredWidthAt`, `uncoveredMarginPx`) assumes every uncovered slot is `cardW = 100px` wide. With multiple uncovered pairs + outlines in `.battlefield-tinted-box`, the DOM row overflows by `36px` per uncovered `.table-pair` and breaks `uncoveredMarginPx` spacing.
- **Fix:**
  - In `frontend/src/styles/table.css` (and `frontend/src/components/TablePair.tsx` if needed), only reserve `padding-right: var(--pair-defense-offset, 36px)` on covered pairs (`.table-pair[data-covered="true"]` / `.table-pair-covered-collapsed`), and set `padding-right: 0` on uncovered pairs (`.table-pair[data-covered="false"]`) so their DOM width matches `cardWidth` (`100px` desktop / `48px` mobile) 1:1 with `computeTableBoutLayout`.
  - Keep `.table-pair[data-covered="false"]` vertically aligned on the same baseline (`padding-bottom: var(--bout-card-offset, 18px)` desktop / `10px` mobile) so covered pairs, uncovered pairs, `.throw-in-outline`, and `.redirect-outline` remain aligned on one horizontal row.

### 2. Eliminate Vertical Viewport Clipping on `1280×800` Desktop (`table.css` / `app.css`)
- **Problem:** At `1280×800`, `[data-zone="table-arena"]` spans `y = 127..957` (`830px` tall) and `[data-zone="player-hand"]` spans `y = 577..847`, clipping the bottom of `.hand-cards` (`~839px`) and Row 4 `[data-zone="player-controls"]` (`y = 872..922`) below `window.innerHeight = 800`.
- **Fix:**
  - Tighten the desktop vertical rhythm in `frontend/src/styles/table.css` (and `.game-header` / `.game-shell` padding in `frontend/src/app.css` if helpful) so that at `1280×800`:
    1. `[data-zone="player-hand"]` and all rendered `.hand-cards` (including lifted/selected cards and any hand size up to 30+ cards) stay strictly within the `800px` viewport (`cardRect.bottom <= 800`), with `[data-zone="player-controls"]` also visible without scrolling if space permits.
    2. Preserve sufficient `--hand-timer-clearance` above `.hand-clock` and `row-gap` below `.hand-clock` so incoming cards from a bottom-seat surrender (`translateY(calc(50% + 12px))` on `.table-pairs-group`) never touch or overlap `.hand-clock` or `.hand-cards` (adjusting `--battlefield-height`, `--seat-row-height`, `--hand-row-height` formula, arena `padding`, and grid `gap` consistently).
    3. Keep card dimensions (`100px × 140px` desktop, `48px × 68px` below `900px`) unchanged.
