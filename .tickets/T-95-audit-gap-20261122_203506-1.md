# T-95-audit-gap-20261122_203506-1: Center-Lock Dragged Card to Mouse Cursor Across All Drag Paths (Including Hand-Reorder Mouse Drag)

## Context & Audit Finding
Item #3 of the current human QA feedback requires:
> *"Compared to the previous version it seems somewhat better, but still there are cases where the mouse cursor and card are not aligned correctly. The center of the card should be perfectly locked to the mouse cursor when clicked, regardless of which part of the card was actually clicked on."*

While the HTML5 drag-and-drop path (`onDragStart` / `onDrag` -> `[data-testid="drag-card-preview"]` with `getTransparentDragImage()`) was updated to center-lock the floating preview, the **mouse-based hand-reorder drag path** (`.hand-card-wrapper[data-dragging="true"]` driven by `onMouseDown` / `mousemove` / `mouseup` and inline `wrapper.style.transform`) still preserves the initial click/grab offset (or tracks the left edge) instead of locking the card's center to the mouse cursor.

This is directly evidenced in the current test suite:
- `frontend/src/__tests__/GamePage.test.tsx` asserts `expect(wrapper.style.transform).toBe('translate3d(28px, 30px, 0)')` right before `fireEvent.mouseUp(document, { clientX: 70, clientY: 50 })` — preserving the `(10, 20)` click offset rather than locking the card's center `(cardWidth / 2, cardHeight / 2)` to `(70, 50)`.
- `frontend/src/__tests__/GameTable.test.tsx` asserts `expect(wrapper.style.transform).toBe('translate3d(88px, 40px, 0)')` with the comment `"The rendered left edge still tracks the pointer exactly"`.

When a player drags an overlapped card in their hand (where only the left `36px` corner strip is clickable), preserving the grab offset or tracking the left edge leaves the dragged card visibly shifted away from the cursor instead of centered underneath it.

## Requirements
1. **Center-Lock Mouse-Based Hand-Reorder Drag (`frontend/src/components/GameTable.tsx`):**
   - Update the pointer/mouse hand-reorder drag positioning logic so that whenever `.hand-card-wrapper[data-dragging="true"]` is actively dragged, the card's **exact geometric center** (`cardWidth / 2`, `cardHeight / 2`, using the active desktop `100×140` or mobile `48×68` card dimensions) is locked directly to the mouse pointer `(clientX, clientY)` — **completely independent of where on the card the user clicked** (`mouseDown` offsetX/offsetY must NOT create an offset).
   - Compute the inline `translate3d(tx, ty, 0)` relative to the dragged wrapper's untransformed resting slot position inside the hand box (`boxRect.left + slotRestingOffsetX`, `boxRect.top`):
     - `tx = (clientX - boxRect.left - cardWidth / 2) - slotRestingOffsetX`
     - `ty = clientY - boxRect.top - cardHeight / 2`
   - Ensure this holds accurately for **every card index (`0` through `N - 1`)**, regardless of:
     - the Item 6b small-hand `32px` parting runway (`HAND_SMALL_HAND_PARTING_PAD_RATIO`),
     - hover parting offsets present at the moment the user clicks,
     - vertical lift (`ELIGIBLE_LIFT_PX` / `SELECTED_LIFT_PX`) on the clicked card,
     - hand size (small 6-card hand, 14-card expanded hand, or 30-card compressed hand).
2. **Verify Parity on HTML5 Play-Drag Preview (`frontend/src/components/GameTable.tsx`):**
   - Confirm `[data-testid="drag-card-preview"]` is identically center-locked to `(clientX - cardWidth / 2, clientY - cardHeight / 2)` immediately from `dragstart` through every `drag` event (ignoring synthetic browser `(0, 0)` drag coordinates on drop/cancel) regardless of which part of the card was clicked or which card index is dragged.
   - Ensure the native browser drag ghost remains suppressed via `getTransparentDragImage()` so no offset secondary ghost appears.
3. **Update & Expand Tests (`frontend/src/__tests__/GameTable.test.tsx`, `frontend/src/__tests__/GamePage.test.tsx`):**
   - Update the existing hand-reorder drag assertions in `frontend/src/__tests__/GamePage.test.tsx` and `frontend/src/__tests__/GameTable.test.tsx` to verify center-locked `translate3d(...)` positioning relative to the slot and pointer `(clientX, clientY)`.
   - Add unit tests proving that for **both** mouse-reorder dragging and HTML5 play-dragging:
     - Clicking the top-left corner (`+5px, +5px`), the visible `36px` strip (`+18px, +20px`), the center (`+50px, +70px`), or the bottom-right corner (`+95px, +135px`) of the same card all yield the **exact same center-locked card position** at any given `(clientX, clientY)`.
     - Dragging the leftmost card (index `0`), a middle card, and the rightmost card (index `N - 1`) in both a small hand (with the `32px` runway) and a large overlapped hand all center the dragged card directly on `(clientX, clientY)` with zero index-dependent horizontal drift.
