# T-05: Game Initialization — Shuffle, Deal, Trump, First Attacker

## Objective
Implement `GameEngine.createGame(config, playerNames)` that produces a fully initialized `GameState` ready for the first `InitialAttack`.

## Requirements

### File: `backend/src/main/scala/durak/engine/GameEngine.scala`

Create an object `GameEngine` with:

```scala
object GameEngine:
  def createGame(config: GameConfig, playerNames: Vector[String]): GameState
```

**Logic for `createGame`:**
1. Validate `playerNames.size == config.playerCount` and `playerCount in {2, 3, 4}`.
2. Generate the deck via `Deck.forPlayerCount(config.playerCount)`.
3. Shuffle using `new scala.util.Random(config.seed)` — use `random.shuffle(deck)`.
4. Deal 6 cards to each player sequentially (first 6 to player 0, next 6 to player 1, etc.).
5. The next card after all hands are dealt is the `bottomTrumpCard`. Place it logically at the **bottom** of the remaining talon (it will be the last card drawn). Set `trumpSuit` from this card's suit.
   - Implementation: after dealing, the remaining cards form the talon. The first of these remaining cards is the revealed bottom trump. Rearrange so `bottomTrumpCard` is `talon.last` and set `trumpSuit`.
6. **First attacker:** Find the player holding the lowest-rank trump card. If no player has a trump, `attackerIdx = 0`. `defenderIdx = nextActivePlayerIdx(attackerIdx)`.
7. Set `boutPhase = BoutPhase.InitialAttack`, `defenderInitialHandSize = players(defenderIdx).hand.size` (which is 6).

### Test File: `backend/src/test/scala/durak/engine/GameInitSuite.scala`

- **Deterministic shuffle:** Creating a game with the same seed twice yields identical states.
- **Hand sizes:** Every player receives exactly 6 cards after init.
- **No duplicate cards:** All cards across hands + talon are unique and sum to deck size.
- **Trump suit:** `trumpSuit` matches `bottomTrumpCard.get.suit`.
- **Bottom trump position:** `talon.last == bottomTrumpCard.get`.
- **First attacker — has trump:** Seed the game so at least one player has a trump. Verify the player with the lowest trump rank is `attackerIdx`.
- **First attacker — no trump:** Construct a scenario (or find a seed) where no player holds a trump card in their initial hand. Verify `attackerIdx == 0`.
- **Defender is clockwise:** `defenderIdx == (attackerIdx + 1) % playerCount` (when all players are active).
- **Bout phase:** `boutPhase == BoutPhase.InitialAttack`.
- **Player count validation:** Passing mismatched `playerNames.size` vs `config.playerCount` throws an exception.

## Acceptance Criteria
- [ ] `GameEngine.createGame` produces valid initial states
- [ ] All `GameInitSuite` tests pass

# T-06: Initial Attack & Defense (Cover) Move Processing

## Objective
Implement `GameEngine.applyAction` for `InitialAttack` and `CoverCard` actions with full validation and state transitions.

## Requirements

### File: `backend/src/main/scala/durak/engine/GameEngine.scala`

Add to `GameEngine`:

```scala
def applyAction(state: GameState, action: GameAction): Either[String, GameState]
```

Returns `Left(errorMessage)` for illegal moves, `Right(newState)` for valid moves.

#### `InitialAttack(playerId, cards)` handling:
- **Validations:**
  1. `boutPhase == BoutPhase.InitialAttack`
  2. `playerId` matches `players(attackerIdx).id`
  3. `cards.nonEmpty`
  4. All cards in `cards` are in the attacker's hand
  5. All cards share the exact same `Rank`
  6. `cards.size <= maxBoutAttacks`
- **State transition:**
  1. Remove played cards from attacker's hand
  2. Add each card as `TablePair(card, None)` to `tablePairs`
  3. Set `boutPhase = BoutPhase.Defense`

#### `CoverCard(playerId, attackIndex, defenseCard)` handling:
- **Validations:**
  1. `boutPhase == BoutPhase.Defense`
  2. `playerId` matches `players(defenderIdx).id`
  3. `defenseCard` is in the defender's hand
  4. `attackIndex` is a valid index into `tablePairs`
  5. `tablePairs(attackIndex).defense.isEmpty` (not already covered)
  6. Legal cover check:
     - `(defenseCard.suit == attackCard.suit && defenseCard.rank.value > attackCard.rank.value)` OR
     - `(defenseCard.suit == trumpSuit && attackCard.suit != trumpSuit)`
- **State transition:**
  1. Remove `defenseCard` from defender's hand
  2. Update `tablePairs(attackIndex)` to include the defense card

# T-07: Redirect / Reflect Mechanic

## Objective
Implement `GameEngine.applyAction` for `RedirectAttack` with full validation, role rotation, and `defenderInitialHandSize` update.

## Requirements

### In `GameEngine.applyAction`:

#### `RedirectAttack(playerId, cards)` handling:
- **Validations:**
  1. `boutPhase == BoutPhase.Defense`
  2. `config.allowRedirect == true`
  3. `playerId` matches `players(defenderIdx).id`
  4. ALL table pairs have `defense.isEmpty` (zero cards are currently covered)
  5. `cards.nonEmpty` and all cards in `cards` are in the defender's hand
  6. All cards in `cards` have the **exact same Rank** as the existing attacking cards on the table
  7. Compute `nextDefIdx = nextActivePlayerIdx(defenderIdx)` (the player clockwise after current defender, who is NOT the current defender)
  8. `players(nextDefIdx).hand.size >= (tablePairs.size + cards.size)` — next defender must have enough cards
  9. `(tablePairs.size + cards.size) <= 6` — total cannot exceed 6
- **State transition:**
  1. Remove played cards from the (old) defender's hand
  2. Add each card as `TablePair(card, None)` to `tablePairs`
  3. Old `defenderIdx` becomes new `attackerIdx`
  4. `nextDefIdx` becomes new `defenderIdx`
  5. Update `defenderInitialHandSize` to `players(nextDefIdx).hand.size`
  6. Reset all players' `hasPassed` to `false`

### 2-Player Redirect Note
In a 2-player game, after redirect the original attacker becomes the new defender. Ensure `nextActivePlayerIdx(defenderIdx)` correctly returns the original attacker in this case.

### Test File: `backend/src/test/scala/durak/engine/RedirectSuite.scala`

- **Valid redirect (2P):** Defender redirects with a matching-rank card; roles swap
- **Valid redirect (3P):** Defender redirects; attack passes to the next clockwise player
- **Reject:** `config.allowRedirect == false`
- **Reject:** Some cards on the table are already covered
- **Reject:** Redirect cards have a different rank than table cards
- **Reject:** Next defender doesn't have enough cards
- **Reject:** Total table pairs would exceed 6
- **Reject:** Cards not in defender's hand
- **Role rotation correctness:** After redirect, `attackerIdx` is the old defender, `defenderIdx` is the next clockwise player
- **`defenderInitialHandSize` update:** Correctly set to new defender's hand size after redirect
- **Chain redirect (3P):** Defender A redirects to B, then B redirects to original attacker (if conditions met)

# T-09: Pass Logic & Bout Resolution (Draw, Discard, Role Rotation)

## Objective
Implement `PassTurn` action handling and the complete bout resolution logic: card drawing, discard/pickup, and attacker/defender role rotation for the next bout.

## Requirements

### In `GameEngine.applyAction`:

#### `PassTurn(playerId)` handling:
- **Validations:**
  1. `boutPhase` is `Defense` or `SurrenderThrowIn`
  2. `playerId` is NOT the defender
  3. `playerId` is an active player
  4. Player has not already passed (`hasPassed == false`)
  5. During `Defense` phase: all attacking cards must be covered (`tablePairs.forall(_.defense.isDefined)`) OR `tablePairs.size >= maxBoutAttacks`
- **State transition:**
  1. Set the player's `hasPassed = true`
  2. Check if all active non-defending players have now passed (auto-pass players with 0 cards or where table is full)
  3. If all have passed → trigger bout resolution (see below)

#### Bout Resolution — `resolveBout(state: GameState): GameState`

Implement as a private helper. Called when all non-defenders have passed.

**Determine outcome based on `boutPhase`:**

**Case A — Successful Defense** (phase was `Defense`, all cards covered):
1. Move all table cards (attack + defense) to `discardPile`
2. Clear `tablePairs`
3. Draw cards (see draw order below)
4. **Role rotation:** old `defenderIdx` becomes new `attackerIdx`; new `defenderIdx` = `nextActivePlayerIdx(new attackerIdx)`
5. Set `boutPhase = BoutPhase.InitialAttack`

**Case B — Surrender** (phase was `SurrenderThrowIn`):
1. Defender picks up ALL cards from the table (both attack and defense cards) into their hand
2. Clear `tablePairs`
3. Draw cards — but **defender does NOT draw** (they just picked up cards)
4. **Role rotation:** new `attackerIdx` = `nextActivePlayerIdx(defenderIdx)` (skip the defender); new `defenderIdx` = `nextActivePlayerIdx(new attackerIdx)`
5. Set `boutPhase = BoutPhase.InitialAttack`

**Card Drawing Order** (while `talon.nonEmpty` and player has < 6 cards):
1. Primary attacker draws to 6
2. Other non-defending active players draw to 6 in clockwise seat order from attacker
3. Defender draws to 6 last (skipped entirely in Case B)

After drawing, set `defenderInitialHandSize` to the new defender's hand size.
Reset all players' `hasPassed = false`.

### Test File: `backend/src/test/scala/durak/engine/BoutResolutionSuite.scala`

**Pass Tests:**
- Valid pass when all cards covered
- Reject: pass when uncovered cards remain (Defense phase)
- Reject: defender tries to pass
- Reject: player already passed
- Auto-pass players with empty hands

**Successful Defense Tests:**
- Table cards go to discard pile
- Players draw to 6 in correct order (attacker first, defender last)
- Roles rotate: defender becomes attacker
- Bout phase resets to `InitialAttack`

**Surrender Tests:**

- Non-defenders draw (defender does not)
- Roles skip surrendering defender

**3-Player Role Rotation:**
- After successful defense in 3P: verify correct attacker/defender cycling
- After surrender in 3P: verify defender is skipped for attack turn

# T-10: Endgame — Player Elimination, Victory Conditions, Draw Detection

## Objective
Implement post-bout player elimination checks, finish ordering, game-over detection, and the 2-player simultaneous draw condition.

## Requirements

### In `GameEngine` (extend `resolveBout` or add `checkEndgame`):

After the draw phase of bout resolution, add an endgame check step:

#### Player Elimination
- When `talon.isEmpty`: any active player whose `hand.isEmpty` is **eliminated** (finished the game successfully).
- Set their `finishRank` to `finishOrder.size + 1` and append their `id` to `finishOrder`.
- Process eliminations in a consistent order (by seat index).

#### 2-Player Draw Detection
- After a successful defense bout (Case A), if `talon.isEmpty` and both remaining players have `hand.isEmpty` simultaneously (attacker played last cards, defender covered with last cards), mark `isDraw = true`, and both players are added to `finishOrder` with the same `finishRank`.

#### Game Over Check
- After eliminations, if `activePlayersWithCards.size <= 1`:
  - If exactly 1 player remains with cards: they are the **Durak** (last place). Set their `finishRank` to `finishOrder.size + 1`, add to `finishOrder`.
  - Set `boutPhase = BoutPhase.GameOver`.
- If `activePlayersWithCards.size == 0` (all players finished, e.g., 2-player draw): set `boutPhase = BoutPhase.GameOver`.

### Test File: `backend/src/test/scala/durak/engine/EndgameSuite.scala`

# T-11: PlayerGameView Projection & Circe JSON Codecs

## Objective
Implement the `PlayerGameView` projection that strips hidden information from `GameState`, and define Circe JSON encoders/decoders for all engine types and WebSocket messages.

## Requirements

### File: `backend/src/main/scala/durak/engine/PlayerGameView.scala`

```scala
case class PublicPlayerSummary(
  id: String,
  name: String,
  cardCount: Int,
  hasPassed: Boolean,
  finishRank: Option[Int]
)

case class PlayerGameView(
  myId: String,
  myHand: List[Card],
  opponents: List[PublicPlayerSummary],
  tablePairs: Vector[TablePair],
  talonCount: Int,
  bottomTrumpCard: Option[Card],  // None when talon is empty
  trumpSuit: Suit,
  attackerIdx: Int,
  defenderIdx: Int,
  boutPhase: BoutPhase,
  legalActions: List[String],     // e.g. ["attack", "cover", "pass", "surrender", "redirect", "throwIn"]
  finishOrder: Vector[String],
  isDraw: Boolean,
  maxBoutAttacks: Int
)

object PlayerGameView:
  def forViewer(state: GameState, viewerId: String): PlayerGameView
```

**`forViewer` logic:**
1. Find the viewer's `PlayerState` by `viewerId`.
2. `myHand` = viewer's hand as `List[Card]`.
3. `opponents` = all other players mapped to `PublicPlayerSummary` (only `cardCount`, never actual cards).
4. `talonCount` = `state.talon.size`.
5. `bottomTrumpCard` = `state.bottomTrumpCard` only if `talon.nonEmpty`, else `None`.
6. Compute `legalActions` for this viewer based on current state (what actions the viewer can currently perform).

### File: `backend/src/main/scala/durak/engine/JsonCodecs.scala`

Provide Circe `Encoder` and `Decoder` instances for:
- `Suit`, `Rank`, `Card`
- `TablePair`, `BoutPhase`
- `PublicPlayerSummary`, `PlayerGameView`
- `GameAction` (all variants, for receiving WebSocket commands)

Use `circe-generic` semi-auto derivation or manual codecs. Ensure:
- `Suit` and `Rank` serialize as lowercase strings (e.g., `"hearts"`, `"ace"`)
- `Card` serializes as `{"suit": "hearts", "rank": "ace"}`
- `GameAction` uses a `"type"` discriminator field (e.g., `{"type": "initialAttack", "playerId": "...", "cards": [...]}`)

### File: `backend/src/main/scala/durak/server/GameActor.scala`

```scala

import cats.effect.*

import fs2.concurrent.Topic

case class GameRoom(
  gameId: String,
```

**REST Endpoints:**
